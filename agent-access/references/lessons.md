# Lessons learned

Each lesson cost a review round, a failed CI run or a fix after release in n8n-ops or Comply. Each one names what happened, the rule that follows, its source, and what guards it now. "Contract suite" means `templates/test/contract.test.mjs`. "Reference" means the rule is in one of this skill's reference files and the adopting product's own tests must guard it.

## The client skill

1. **Show the link and the code in the reply that ends the turn.** Agents kept working after `connect` and printed the link between commands. Agent apps fold that text, so the person never saw it. The `next` hint, the client `SKILL.md` and the install note now all say to end the turn with the link and the code. Source: n8n-ops PR #44. Guard: the contract suite checks the exact `next` text.
2. **Key the connection by the product's address, in the user's home.** A first design wrote an install id into the skill's folder: each install became its own connection, a Git-managed copy got dirty, and Node and PowerShell disagreed on the folder's path on Windows (8.3 short names). The connection is now a file in `~/.<product>` named by a hash of the issuer, shared by every agent install of the user. Source: n8n-ops PRs #42 and #177. Guard: contract suite ("shares one connection", "never writes in the skill's folder").
3. **Keep the address after a successful connect.** A copy installed from Git has no address filled in. The command keeps the address of the last working connection and uses it when none is given. A kept address with a second line is invalid, not another address. Source: n8n-ops PR #177, Comply c75ad19. Guard: contract suite ("keeps the address").
4. **Quote the address in every printed command, and accept only a plain origin.** zsh and bash with `failglob` read the brackets of `http://[::1]:8080` as a file pattern and refused the hint. URL parsers in Node and .NET keep characters such as `$(` and `;` in a host. Every hint, message and install note now quotes the address, every version accepts only a plain origin with a port from 1 to 65535, and the server serves the skill only for such an address. Source: n8n-ops PR #198, Comply 29a92bf and ee9f9f2. Guard: contract suite runs each hint in bash with `failglob`, zsh and PowerShell against an IPv6 address.
5. **Run `whoami` and `icacls` from System32.** Under Git Bash, its own `whoami` comes first on the `PATH` and prints something else. Source: n8n-ops PR #42 (found in the live check). Guard: contract suite ("another whoami first on the PATH").
6. **Read the Windows ACL back.** Granting with `icacls` does not remove other entries. After limiting the folder, make the user the owner (`/setowner`, after the grant, without `/C`, whose exit code 0 hid failures), save the ACLs with `/save`, and refuse any other allow entry or any entry that is not a plain allow or deny. The built-in Administrator account shows as `LA` in SDDL. Source: n8n-ops PR #42. Guard: contract suite (Windows ACL cases).
7. **Open files with `FileShare` `ReadWrite` and `Delete` in PowerShell.** `ReadAllText` shares a file for reading only, so another command could not replace the record or delete the lock meanwhile, and failed. The ten-commands-at-once test failed about once in twenty runs and then failed CI on `main`. Source: n8n-ops PR #154. Guard: contract suite ("ten commands refresh once").
8. **Treat an answer that broke off as sent.** The server got the request and may have spent a one-time secret. Source: n8n-ops PR #42. Guard: contract suite.
9. **Persist the refresh start, and give a refresh in flight its grace.** A holder that lost its lock may still be waiting for the server's answer. Write `refreshStartedAt` before sending. Never send a refresh that started under 30 seconds ago. Retry a lost refresh once: that continues the connection or ends it, which also ends the token nobody received. Source: n8n-ops PR #42. Guard: contract suite.
10. **Keep old tokens until the server confirms their end.** After `connect --replace`, the old connection is revoked only once the new one is stored, and a token that could not be revoked stays in the file to try again, also when the new connection ends. Source: n8n-ops PR #42. Guard: contract suite.
11. **Recognize a lock that came back.** Another process may move a lock aside by mistake and put it back. Its holder must keep its new tokens anyway, under a fresh lock. Source: n8n-ops PRs #42 and #205. Guard: contract suite.
12. **Wait when Windows refuses a just-deleted file name.** Creating a lock whose name is still being deleted fails for a moment. Source: n8n-ops PR #42. Guard: contract suite (lock cases on Windows).
13. **Never use .NET `HttpClient` for one-time secrets.** In Comply's tests, in PowerShell 7, it re-sent a dropped request four times, which spends a refresh token twice and ends the connection. n8n-ops did not reproduce it in nine plain-HTTP cases (PowerShell 5.1 and 7, fresh and pooled connections). The PowerShell version speaks HTTP over a raw socket as a precaution. Source: Comply's client (`comply.ps1`, comment on its request function). Guard: contract suite (lost refresh answer, on `ps` and `pwsh`).
14. **Never send an action twice.** An `act` call whose answer was lost, or that got a server error, answers `outcome_unknown`. Resend only after a refusal the server makes before route code runs. Fail closed when the endpoints list cannot be read. Source: Comply's client, made stricter when this skill was reviewed. Guard: contract suite.
15. **Tell an agent its skill is old, but never force it.** A copy installed from Git belongs to whoever installed it. Source: Comply c75ad19. Guard: contract suite (version header), and the product's test of `update_skill`.

## The authorization server

16. **Pass exactly the library's own paths.** The provider also accepted a trailing slash or another letter case, which slipped past the product's checks in front of it. Compare the raw path with the routed one, and pass only exact provider paths. Source: n8n-ops PR #41. Guard: reference (`server-oauth.md`).
17. **Consume atomically. Any revoke ends the grant.** Two requests with one refresh token at once must not both win. Revoking an access token alone left the grant alive. Source: n8n-ops PR #41. Guard: reference (S13, S15).
18. **Turn off what the resources do not check.** Sender-constrained tokens (DPoP) that the resources never verify, pushed authorization requests that skip the authorize checks, and registration access tokens nobody needs, are all off. Source: n8n-ops PR #41. Guard: reference (`server-oauth.md`).
19. **The person decides, not the registration.** A client's requested scopes at registration are dropped, and the 401 challenge names every scope, so the consent page offers them and the person picks. Source: n8n-ops PR #41. Guard: reference.
20. **Look again before ending an "unused" connection.** A refresh marks the old token used just before it stores the new one, so a sweep at that moment saw no live token. Count a token used in the last minutes as live, and look again a moment later. Source: n8n-ops PR #41. Guard: reference.
21. **Use exactly `localhost`, `127.0.0.1` and `::1` for loopback.** The rule accepted all of `127.0.0.0/8`, while the scripts allowed three names. Source: Comply 9c52b85. Guard: reference (S3).
22. **CIMD fetches ignore the admin's trusted hosts.** A host an admin trusts for form integrations let a stranger's `client_id` URL reach a private address. Source: Comply 318f9d1. Guard: reference (S6).
23. **Count rate limits before the first `await`.** A limit checked before the request and counted after it let requests sent at once all pass. Count first, and give a device poll back once its code turns out to be waiting or approved, exactly the event it counted. Source: Comply 4a8ed86, e4a0cc4 and 57023ee. Guard: reference (S20).
24. **Caps hold under parallel requests only with a lock.** Adding a registration or a device request under a cap takes a transaction advisory lock first. Source: Comply 4a8ed86. Guard: reference (S5, S9).
25. **Expired means ended for good.** A check that only refused a connection past its end let a longer maximum revive it. A check or a refresh that finds it past its end now ends it, and saving a new maximum first ends every connection past its end under the old one. Source: Comply 0b46f40. Guard: reference (S17).
26. **Keep one lock order everywhere.** Writing an audit row for a person takes a key-share lock on that person through the foreign key. Revoking locked grants first and wrote that row after, while a change to the person locked the person and then the grants: a deadlock. Every path now locks the gate, then people in id order, then pending requests and codes, then grants, then tokens. The consent answer takes the gate and the person before it takes the pending request, so "disconnect all" either dropped it or ends what it made. Source: Comply 2b873dd, 57023ee and c4de367. Guard: reference (S19) and the race matrix in `testing.md`.
27. **The issuer or identity provider changed: end everything.** Connections made under another public URL ended only when the provider was rebuilt. Reconcile at start-up and in the sweep too. Source: n8n-ops PR #41. Guard: reference (S18).

## People's pages

28. **Keep "disconnect all" available with no active connection.** It also cancels waiting codes, device requests and approvals. Source: Comply 41dab86. Guard: reference (`consent-and-management.md`).
29. **Lists that refresh by themselves need the background allowlist.** The connection lists re-read every 30 seconds, but their routes were not on the product's background-request allowlist, so every refresh was refused. Source: Comply bda9182. Guard: the product's own tests.
30. **Do not cut tool answers below the answer limit.** An extra 100,000-character cap sent valid answers as cut JSON with no way to read the rest. Keep one limit, and mark a cut answer. Source: Comply 405e1be. Guard: reference (`policy-and-channels.md`).

## Temporary access

31. **Keep access until the result is checked.** The skill told agents to release access as soon as the change was made, so a change that then failed needed a new request and a new approval. Agents now keep it while they check, fix or wait for the person, within the approved minutes and reason. Source: n8n-ops PR #179. Guard: reference (`temporary-access.md`).
32. **Use `revision` against decisions made on a stale view.** An approver could approve what another approver had just changed. Approval names the revision it saw. Source: n8n-ops PR #185. Guard: reference.
33. **A release never fails on its summary.** A long summary is clipped, never refused, so it cannot keep a key alive. Source: n8n-ops PR #183. Guard: reference.
34. **Notify channels only when the person asked.** Source: n8n-ops PR #186. Guard: reference.
35. **Secrets never pass through the conversation.** Source: n8n-ops PR #187. Guard: reference.

## CI

36. **Run the skill's tests when only the skill changes, and never weaken a check to get there.** A change-detection filter selected only the skill's package, and the run failed for a missing script. The fix left the skill out of one step by name, rather than letting any package skip a missing test script. Source: n8n-ops PRs #154 and #203. Guard: the product's CI.

## Bringing a product up to this standard

These came from bringing n8n-ops and Comply up to this skill. Most blockers in those reviews were about the lifecycle of a connection and about concurrency, not about the protocol.

37. **Hash what the library lets you hash, and pin why it works.** With `oidc-provider`, an adapter can store access tokens, refresh tokens and codes as hashes, because the library looks them up only by the presented value. Device codes cannot be hashed, because the library finds them again by their stored id. The approach rests on undocumented behavior, so a test fails when it changes. Source: n8n-ops PR #214. Guard: reference (S16).
38. **Check what the MCP SDK does with `Origin` before relying on it.** The TypeScript SDK marks its origin options deprecated in favor of middleware. The Python SDK checks `Host` together with `Origin`, so a proxy that rewrites `Host` makes every call fail with 421, and the server's logs did not show `Host`. Verify the `Host` each deployment path delivers before turning the check on. Source: n8n-ops PR #214, Comply PR #118. Guard: reference (`policy-and-channels.md`, `testing.md`).
39. **The issuer is spelled the way a browser spells it.** A configured public URL with non-ASCII letters, a short IPv4 form or an IPv4-mapped IPv6 address differed from the `Origin` browsers send, so real approvals got 403. The product now refuses such a URL instead of normalizing it. It took three review rounds. Source: Comply PR #118. Guard: reference (S3).
40. **The consent page and its POST use one set of areas.** The POST checked only the areas the person may use, so a forged POST could add an area the agent never asked for. Source: aligning an existing implementation with this standard (a plan review blocker). Guard: reference (`consent-and-management.md`).
41. **The library may end its grant before the product's record ends.** On refresh reuse the library deleted its grant and fired the event later, so a token just issued to the winning request passed the check for a moment. Local runs passed, and CI caught it. The per-call check now also requires the library's grant. Source: n8n-ops PR #214. Guard: reference (S17) and the race matrix.
42. **Use a counter, not a timestamp, to order a flow against an end.** The database's `now()` is the transaction's start, and the library sets `iat` when it saves a token, so no time proves that a flow began before "end everything". A generation counter raised under the gate does. Source: n8n-ops PR #214. Guard: reference (S19).
43. **An end is one transaction, and every path that ends a grant ends what hangs on it.** The library's own revocation and reuse paths delete records directly, so a temporary-access key already collected kept working until it checked the grant. Source: n8n-ops PR #214. Guard: reference (`architecture.md`, `temporary-access.md`).
44. **Identity-change hooks need the same care as any other end.** A hook that ran before a two-factor reset did not check the caller, so an unauthenticated request could disconnect every agent. Other review findings: a session read error skipped the end, a shared "reset in progress" flag was cleared by another reset, and an error left approvals blocked until restart. Source: n8n-ops PR #214 (six result review findings). Guard: reference (`server-oauth.md`, identity changes).
45. **Release locks on every path, and keep quotas apart.** A lock released on a timer, a lock left held after a failed database read, a per-session limit keyed by text the caller sends, and one quota shared by device polls and `/token` all failed review. Source: n8n-ops PR #214. Guard: reference (S20).
46. **A refusal made before anything changed is not a 5xx.** Temporary access answered 503 for `busy`, so the new client reported `outcome_unknown` although nothing was saved. Source: n8n-ops PR #214. Guard: reference (`policy-and-channels.md`).
47. **Write one audit entry per call, from one owner.** Auditing every REST call took four plan review rounds: who writes it, when the slot is released, what a call past the deadline or a broken answer records, and what happens on shutdown. Source: Comply PR #118. Guard: reference (`policy-and-channels.md`).
48. **A client change the server enforces is a rollout, not a notice.** Old copies sent no policy headers and got 409 on every call, and a new copy installed from the default branch failed against a server not yet deployed. The 409 now names how to reinstall, and the server is released and deployed before installers move. Source: n8n-ops PR #214, Comply PR #118. Guard: reference (`distribution-and-versioning.md`).
49. **Audit by testing each requirement, not by reading the code.** A reused device code was refused but left its grant alive, in an implementation that already met most of this standard. Tests written for each requirement found it. Source: aligning an existing implementation with this standard. Guard: reference (`testing.md`).
