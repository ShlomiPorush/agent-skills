# UI behavior rules (v3 style): Charts

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `0210d15` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Charts

- **CH-1 Pick a bar to see that hour.** Each of the last 24 hours is a bar of clean mail with spam stacked on it, height `value / max * 100%` with `max = max(1, ...)`, zero segments hidden (`i[style*="height: 0%"]`), legend Clean / Spam, under a time axis that names every third hour (bold every sixth) and ends with "Now"; the last label never overflows the chart's end (`text-align: end; direction: rtl`). Hours are named in the app's time zone (`formatInZone`) and counted from the epoch, so any zone lines up with the UTC buckets; the bars and axis stay left to right in RTL (`direction: ltr`). Bar hover `ink 6%` only with a pointer (`@media (hover: hover)`); tooltip "14:00 to 15:00: 12 clean, 3 spam. Click for this hour's numbers". Clicking a bar picks that hour: the four figures switch to that hour with the 24-hour figure as the small note, the title becomes "Mail flow, 14:00 to 15:00", other bars fade (`opacity: .3`), and "View these messages" and "All 24 hours" appear. Clicking the same bar again, or "All 24 hours", returns to the day view; a picked hour survives refreshes while it is still in the window. On phones the chart goes from 120px to 90px and only every sixth hour is named (minor labels `visibility: hidden`). Data: `/api/stats/timeline?hours=24`. Keyboard: bars are buttons with `aria-pressed` and a focus-visible ring; chart `role="group" aria-label="Messages per hour"`; axis `aria-hidden`. v3: `pickMailFlowHour()`, `renderMailFlowStats`, `.ui-flow-bars.has-pick`; app.js:2076-2182; ui.css:1257-1294, 2597-2599; index.html:613-617.
- **CH-2 From a picked bar to exactly its rows, with the same count.** With an hour picked, "View these messages" opens the list with a custom range of exactly that hour ("Oct 16, 14:00 to 15:00", end = start + `3600000 - 1` ms) and every other filter cleared; the date picker shows that day and the label names the hour, both in the app's time zone, and the count matches the chart because both use first-seen time. The dashboard figure counts like the Messages page, with deliveries beside it ("511 deliveries, 24h: 1,890"). On DMARC, each day column of "Messages per day" opens that day's reports (the TLS chart the TLS day); a report day has a small 90px "Other days" chart to jump to another day. On the all-domains chart the columns are `disabled` because there is no single domain. Keyboard: columns are buttons (CH-3). Pitfall: the dashboard counted every delivery as a message, so a picked hour showed 511 and its Messages list 283 (#344). A test now checks the dashboard figure against the Messages list total. v3: app.js:2119-2143; dmarc.js:302-304, 830.
- **CH-3 Chart columns are buttons with a tooltip on hover and focus.** Each chart column is a button carrying its label in `data-tip`; hovering (a tap on a touch screen too) or focusing it shows a dark label above it ("Sep 14: 1,204 passed, 3 failed"; TLS "encrypted" and "failed") via `::after { content: attr(data-tip); bottom: calc(100% + 6px); left: 50%; transform: translateX(-50%); z-index: 3 }`, and focus or a hovering pointer brightens it (`filter: brightness(1.15)`, activity charts 1.3); a disabled column has `cursor: default` and does not brighten. The charts read left to right in both directions (`direction: ltr`). DMARC daily bars stack passed (green) under failed (red) with a legend and only the first and last dates on the axis. Y top is rounded up to the next multiple of the power of 10 below the max, with 5 gridlines; heights 150 (home), 190 (domain), 120 (TLS), 90px (other days); column max-width 46px; empty "No reports in the last 30 days.". Reference lines and markers do not catch the pointer (`pointer-events: none`). Keyboard: each column is a `<button>` whose `aria-label` equals the tooltip, and keyboard focus shows the tooltip too. v3: ui.css:2597-2618, 2725-2735; dmarc.js:286-304.
- **CH-4 A sparkline opens its chart dialog.** Each Mailbox Stats row has a tiny `96 x 24px` SVG line of sent plus received messages over the period (area fill accent 18%, 1.5px stroke, `vector-effect: non-scaling-stroke`; a flat grey line when empty), with a zoom cursor and a frame on hover. A click opens a dialog with sent and received columns per day (per hour for Today), a tooltip per column ("Mon, Oct 5: 12 sent, 4 received"; days and hours named in the app's time zone, an hour a clock change repeats shown twice), the Sent, Received, Failed and busiest-day figures, and an "Open its messages" button that closes the dialog and opens Messages filtered on the mailbox. Dialog y top = max rounded up to a multiple of 4 (minimum 4), 5 gridlines; empty "No activity in this range."; Failed red at 10% and above; busiest "-" without activity; subtitle "Full Name · Last 30 Days, aliases included". Keyboard: the sparkline is a `<button>` with `aria-label="Activity of <user>: N messages. Open the chart"`, SVG `aria-hidden`, focus-visible border; dialog `aria-labelledby` the title. v3: `mailboxSparkline`, `openMailboxActivity`; mailbox-stats.js:379-436; ui.css:1657-1664.
- **CH-5 Activity behind an alert: the usual rate and the alert window.** Show the baseline next to the anomaly, plus the context needed to judge it: a volume spike, an SMTP block by abuse protection or an auth failure burst has "Show activity", opening a window with the mailbox's sent mail (or the username's failed logins) per 15 minutes (per hour for the N-day view, several hours a column when the baseline is longer than a week), columns inside the alert window in red, for a spike a dashed amber line for the usual rate labelled "usual: 0.42 an hour" (at least .6% from the bottom; a block shows its limit as a figure instead), a red marker "Alert 14:05", hover "Mon, Oct 5, 14:00: 12 sent" (" in 45 minutes" added when a clock change or the end of the data makes a column shorter or longer), all on a 24-hour clock in the app's time zone. Y-axis top = `max(4, peak)` rounded up to a multiple of 4, grid at quarters; period control 24 hours / 2 days / N days (FS-14). Below: four figures with the alarming ones in red ("The window: Unknown" when the alert's window is not known, and then no columns are marked), "Around the alert" from the window's start to an hour after with bars for recipient domains, outcomes ("What happened to them") and subjects, or addresses, countries and networks, a short note on how to read the pattern, then Open in Messages or Open in Security, and "Dismiss the alert" while it is not dismissed. Subjects get `dir="auto"` with the full text in the tooltip; empty "Nothing in the logs around the alert. They may have been cleaned up since.". Keyboard: Escape closes the window (DS-18). Pitfall: an alert says that something happened, not whether it is spam from a hijacked mailbox or a legitimate mailing, so #387 added this view. A follow-up kept the window's figures visible and its usual-rate label clear of the alert marker. v3: alert-activity.js:34-194; ui.css:2724-2735.
- **CH-6 A flow diagram lays itself out for its width.** Measure in JS and choose the layout by the container width: the DMARC mail flow shows "Your domain", "Sent by" and "Reported by" (top 8 senders, top 8 receivers) joined by curved lines whose width is volume (group `max(3, share * 24)`, link `max(2, share * 24)`, stroke opacity .45, round caps) and color the sender's pass rate (node tones at 95% / 80%). Wide: three columns each centred vertically, node width `min(210, (w - 80) / 3)`, 10px gap, 26px header. Under 600px the columns become rows down the page (44px between rows, 8px between nodes) and column titles hide. Redraw on resize (debounce 150ms) and keep watching the size while hidden so it draws correctly when the screen gets wider; at 760px and below the whole card is hidden (MO-6). A node is a `<button>` only when it has an action (sender nodes open their sender page). Screen reader: SVG `aria-hidden`. v3: dmarc.js:321-401.
- **CH-7 Charts read the theme tokens.** Canvas charts read their colors from CSS tokens with `getComputedStyle` at render, so they match the light or dark theme: blocked sends per hour or day as red bars (`--ui-fail`) on hairline grid lines (`--ui-line`), text `--ui-muted`. Bar chart, no legend, no x grid; x ticks unrotated, `autoSkipPadding: 12`; integer y ticks from 0; bar radius 3; height 180px. Destroy the chart before each reload and make the content visible before drawing so the canvas can measure. v3: rate-limits.js:96-103, 248.
- **CH-8 Meters colored by use.** Storage shows a meter colored by use: ok up to 75%, warn above 75%, fail above 90%, from one level the Status page computes for its meter, its big figure and its Storage KPI; the dashboard's Storage KPI uses the same thresholds, written out again (no shared helper). The blocklist scan shows a filling info meter (LD-13). v3: app.js:2313-2317, 4382-4394, 4475.
