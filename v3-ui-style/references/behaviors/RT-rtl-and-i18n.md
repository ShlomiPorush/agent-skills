# UI behavior rules (v3 style): RTL and i18n

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `1d4f3e0` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## RTL and i18n

- **RT-1 Logical properties and mirrored controls.** Use logical properties only, so start and end padding, insets, borders, badges, popovers and the reading gauge mirror for right-to-left: `margin-inline-start`, `inset-inline-start/end`, `border-inline-start`, `padding-inline-*`, `border-start-*-radius`, `text-align: start/end` (toast `inset-inline-end`, sort arrow `margin-inline-start`, search panel `inset-inline: 0`). Mirror icons and keys under `[dir="rtl"]`: switch knobs slide the other way (`translateX(-16px)`), the domain chevron points left (`.ui-domain-chevron { transform: scaleX(-1) }`), row menus align to the button's left edge from its computed `direction`, the active search result bar and the chosen network row's bar sit on the right (`.ui-gs-item.is-active`, `.ui-sec-net.is-on`: `box-shadow: inset -3px 0 0 ink`), and the sidebar's page flyout opens on the sidebar's other side and slides in from it (`[dir="rtl"] .ui-fly { transform: translateX(4px) }`). Charts keep time running left to right in both directions (`direction: ltr` on the DMARC days, the alert history, the mail flow, the overview strip and the DMARC calendar). Keyboard: the search's Left and Right keys swap (`(event.key === 'ArrowRight') !== rtl`), and the flyout's key back to the sidebar is Left, or Right in RTL; the DMARC calendar's Left and Right do not swap, since its time runs left to right. v3: ui.css:158, 331, 348, 574, 807, 863, 1578, 1726, 2103, 2322-2323, 2468, 2536, 2719, 2723, 2738-2739, 2859, 3052-3053; utils.js:405-406; search.js:585-586; app.js:6177-6179, 6205-6206; dmarc.js:337-351.
- **RT-2 Mixed-direction user text with dir="auto" and bdi.** Put `dir="auto"` on every element holding user-supplied text that may be right-to-left (subjects, rule names, match values, quarantine content, Rspamd history subjects, rate-limit subjects, device names) so it lays out in its own direction inside the page, and wrap copyable emails, IPs and device names in `<bdi>` so they keep their direction inside RTL text. Screen reader: correct bidi reading order. Demo data includes Hebrew and Arabic subjects so this is always exercised. v3: index.html:383-387; utils.js:732; app.js:1227, 3704, 3949, 3970, 4100, 4102, 4407, 4414; message-details.js:913; logs-viewer.js:701; rate-limits.js:566; devices.js:149.
- **RT-3 Fonts per script, downloaded only when used.** Latin, Hebrew and monospace text each render in their own self-hosted font, one `@font-face` per script with `unicode-range` and `font-display: swap`, so the browser downloads only the scripts a page uses: Onest (Latin and Cyrillic), Noto Sans Hebrew, IBM Plex Mono (addresses, IDs, IPs), whose 500 files are declared for `font-weight: 500 900` so a mono value in bold text keeps its real letters instead of a bold the browser fakes; stacks `'Onest', 'Noto Sans Hebrew', ...` and `'IBM Plex Mono', 'Noto Sans Hebrew', ...`. A test fails if a page loads any external font, script, stylesheet or image. v3: ui.css:18-66.
- **RT-4 Labels spelled from keys, readable.** One label function spells a setting's readable name from its key, with acronyms in capitals (SSL, IMAP, TLS, OAuth, OIDC, API, URL, IP, DNS, DMARC, SPF, DKIM, SMTP, CSV, ENV, DB), "Rw" as "(read-write)" and a leading "mailcow" lowercase, plus an override map for labels the key cannot spell well ("Report Import Error Email", "Retention Days", "Time Zone") and for the Outbound settings, named for what they do ("Handle undeliverable mail automatically", "Sync with Rspamd", "Permanent delivery failure", "Exclude these domains"); settings shared by DMARC and TLS drop the "DMARC" prefix (IMAP Host, Retention Days). Search still finds them by key. Help titles read as words: `Help - ${title || docName.replace(/_/g, ' ')}`, the page's own name when it passes one ("Help - Outgoing spam" for `Abuse_Protection`), else the file name ("Help - Mailbox Stats" from `Mailbox_Stats`). Pitfall: names "said DMARC only" although they covered TLS reports too, fixed in #339; help titles showed "Help - Abuse_Protection" until #429. v3: `settingsFieldLabel`; settings.js:15-33, 1107-1120; app.js:6011-6012; search.js:110.
- **RT-5 Country names from the browser; flags in a fixed slot.** The country list of the protection rules comes from the browser in the UI language (`Intl.DisplayNames(['en'], { type: 'region' })`); names on log rows come from the server's GeoIP data; the flag shows wherever a country is named; in Security rows the flag sits in a fixed 16px slot (flag 16x12) before the address so every address starts at the same place; a missing flag image hides or removes itself (`onerror="this.style.display='none'"` or `onerror="this.remove()"`) instead of showing a broken icon. Build a flag URL only from a two-letter code. Screen reader: a flag beside the written name `alt=""` (Security rows, events); the GeoIP lines (`renderGeoIPInfo`, `renderGeoIPForDMARC`) use the country name as `alt`. v3: `getFlagUrl`; app.js:1516, 5787-5792, 5818, 5871; security.js:123-127, 383-386; ui.css:836-837; protection.js:90; app.js:5816, 5836.
