# UI behavior rules (v3 style): Menus, pickers and popovers

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `1d4f3e0` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Menus, pickers and popovers

- **MP-1 One accessible picker for every list filter.** Every list filter uses one drop-down whose button names its filter and value ("Period: Last 7 days", name part weight 500, opacity .75). A short list opens as a listbox (`max-height: min(420px, 60vh)`, options `.ui-fct` buttons with an optional hint such as a count); rich content (custom range, country bars, network list) opens as a small dialog panel. An option can carry a status dot before its label (`dot`: a tone `ok`, `warn`, `fail` or `spam`, `''` for grey), drawn as the Outcome filter draws it (`9px` square, `border-radius: 3px`, `aria-hidden="true"`). Options never scroll sideways: the list hides its overflow (`overflow-x: hidden`), a long label is cut with an ellipsis and its hint stays whole (`flex: none; white-space: nowrap`). Opening moves focus into the panel without scrolling the page (the search field if any, except on a touch-only screen, MP-4; else the chosen option or the first; in a dialog panel its checked radio, else its first control); an `onOpen` hook runs before the panel shows. Up and Down move, Home and End jump, movement stops at the ends; Up from the first option returns to the search field; Enter or Space pick; ArrowDown or ArrowUp on the button opens it. Escape closes only the picker and returns focus to its button. A click outside or tabbing out closes it, also a click inside a dialog (the message dialog lets clicks reach the page, the suppression dialogs still stop them; a backdrop tells its own click apart, DS-9), so a picker inside a dialog opens and one left open on the page closes; only one is open at a time; clicking the button again closes it. After a pick, focus lands on the button on the next frame. In a form (`field: true`, the Settings Time Zone) the picker looks like a select: a full-width `ui-select-btn` that shows only the value, named by the field's label (`labelledBy` becomes `aria-labelledby`), locked by `disabled`, its panel as wide as the field (`min-width: min(280px, calc(100vw - 16px))`) and its arrow turned `rotate(180deg)` while open. Screen reader: WAI-ARIA listbox and dialog patterns; button `aria-haspopup`, `aria-expanded`, `aria-controls`; options `role="option" aria-selected`, `tabindex="-1"` (roving focus), `:focus-visible` inset ring. Pitfall: before #431 a Security picker lost keyboard focus on every open and close, the Messages pickers did not close on Escape, and each page had its own drop-down with different looks and behaviour; #431 unified them and #432 extended them to every list. The option's own handler runs first and may redraw the picker, hence focus on the next frame; catch Escape in the capture phase. The message dialog stopped every click inside it (`stopPropagation` on `.ui-dialog`), so a picker inside never opened and one open on the page stayed open; #483 removed it, as `uiBackdropClick` already tells the backdrop apart. v3: `uiPicker({ id, label, value, set, options: [{label, hint, dot, value, selected, onclick}] | null, panel, panelLabel, panelClass, hostClass, onOpen, search, field, labelledBy, disabled, icon })`, `uiPickerOpen`, `uiPickerClose(..., { returnFocus: true })`; utils.js:2587-2648, 2729-2774, 2830-2920; ui.css:552, 564, 3058-3108; app.js:4574-4586; settings.js:1333-1336; message-details.js:1359-1370.
- **MP-2 An open picker survives page redraws.** If new data redraws the filter bar while a picker is open (counts arriving, a list refresh), it stays open, keeps what was typed in its search, and keyboard focus goes back inside it; if a picker was just closed and the redraw lost focus, focus returns to its button. Keep state `uiPickers = { open, held, query }`, check `uiPickerIsOpen(id)` while drawing, call `uiPickerRefocus()` after `uiFilterBarSync`, drop `held` once focus moves elsewhere. v3: `uiPickerIsOpen(id)`, `uiPickerRefocus()`; utils.js:2608-2628, 2815-2828, 2904-2907; app.js:4719, 4763-4764; security.js:560, 574, 676-677.
- **MP-3 A native select upgraded to a named picker.** A native filter select with `data-picker-label` looks and behaves like the picker pill ("Country: All", "Window: Last 30 days"): hide the select and draw the picker before it; picking sets `selectedIndex` and dispatches a bubbling `change`, so the page code keeps reading its value, options and onchange as before. The pill names the filter, then a short form of the value (`<option data-short>`). A picker whose value is not the default (`data-filter-default`) turns solid (ink background, inverted text), with its chevron rotating from `rotate(45deg)` to `rotate(-135deg)` while open. A picker whose value lives in an input elsewhere (a custom period) still lights up (`.ui-picker[data-state="<input id>"]`, `.ui-msg-range.is-set`). Re-sync labels and set state on each load; a select marked `data-no-filter` (an order rather than a filter) never counts as an active filter. A lone select outside a filter bar becomes a picker the same way (the Rate Limits Window). A list's order is not a select: it is the list's Sort button (TB-28). Other hooks: `data-picker-search`, `data-picker`, `data-on-open`, `data-picker-host` (a class for the picker host: `ui-picker-end` opens toward the start, as the Rate Limits Window does); pickers sit in `.ui-fbar-pickers` with `.ui-picker-slot { display: contents }`. Keyboard: as MP-1. v3: `uiFilterBarSync()`; utils.js:1897-1903, 1909-1944, 2643; ui.css:591-597, 3057-3067; app.js:3201, 3317, 3626; rate-limits.js:32, 117, 195.
- **MP-4 Long lists get a search field.** A picker with more than ten choices (`options.length > 10`, or `data-picker-search`) gets a search field above its options, labelled "Search <label in lower case>" or its own text ("Search countries", "Search time zones"); typing narrows them live (substring, case-insensitive, an underscore counts as a space so "new york" finds America/New_York, non-matches `[role="option"][hidden]`), "No matches" appears when nothing is left, Down moves into the list and Enter picks the first match (with none left Enter does nothing, so it never submits a form around the picker). Opening puts the focus in the search field with a mouse or keyboard; on a screen used by touch only (`(hover: none) and (pointer: coarse)`) the search field does not take the focus, so the on-screen keyboard does not cover the list: the chosen option (else the first) takes it and is scrolled into view inside the panel, and a tap on the field still searches. Closing clears the search, so the next opening lists every choice again. An option can carry a hint at its end (`hint`), and the options take the list's width (`grid-template-columns: minmax(0, 1fr)`), so the hint is never cut. Example: each zone in the Time Zone picker shows how far its clock is from UTC now, daylight saving included ("UTC+03:00", `Intl.DateTimeFormat` with `timeZoneName: 'longOffset'`), and the picker's button shows it after the chosen name, muted. Panel `width: min(320px, calc(100vw - 16px))`, list `max-height: min(320px, 45vh)`. Screen reader: search input `aria-controls`, `aria-autocomplete="list"`, autocomplete and spellcheck off; "No matches" `role="status"`. Pitfall: the search field took the focus on every opening, and on a phone the keyboard it brought up covered the list; #475 opens a long list on its chosen option on touch-only screens. On a phone the options were `10px` wider than the list, so a row's end was cut, until #488 gave them the list's width. v3: `uiPicker({ search: true })`, `settingsZoneOffset`, `settingsZoneButton`, settings.js:869-884, 1332-1334; ui.css:338, 3099; `data-picker-search`, `uiTouchOnly`; utils.js:1939-1940, 2616-2620, 2633-2638, 2755-2801, 2854-2860, 2884-2889; ui.css:3059, 3084-3108; index.html:822.
- **MP-5 Panels stay on screen.** Date and filter panels open under their button and never run off the edge: `.ui-popover { top: calc(100% + 6px); inset-inline-start: 0; z-index: 50; width: 320px; max-width: calc(100vw - 32px) }`; a panel that would pass the left or right edge shifts back in with an 8px margin (`translateX`); picker `max-width: calc(100vw - 16px)`. A picker panel also stays within the room it really has: the screen below a fixed or sticky top bar (`.ui-mtop`) and above a fixed tab bar (`.ui-tabbar`), cut down by every box around the panel whose overflow is not visible (the page's scrolling area, a card, a dialog), 8px in from each end. A button under a bar (reached with the keyboard) is first scrolled to the middle. When the panel would pass the bottom of that room it opens above its button (`.ui-popover.is-up { top: auto; bottom: calc(100% + 6px) }`), but only if the room above, measured where the panel really hangs from (not always its button), is larger than the room below; still taller than the room on its side, it scrolls within it (`max-height` of that room, `overflow-y: auto`). It is placed again on window resize and when a redraw puts the focus back in it. The focus moves inside with `preventScroll`, so the page does not jump, and the chosen item is scrolled into view inside the panel. A picker stays open when a click on a label in it hands the focus to the dialog around it (a layer takes the focus itself); only focus moving to something outside both closes it. Panels at the end of a row open toward the start (the Security period and the Rate Limits Window, `.ui-picker-end`: `inset-inline-end: 0; width: 220px`; a Sort menu, `width: 240px`); on phones they span the width with margins (`inset-inline: 16px; width: auto`). At 1279px and below the Messages pickers host is `position: static` so the panel starts at the row start. Pitfall: the time panel ran off the right edge until #342 opened it from the start of the summary row, and panels were cut at the screen edge on phones until #432. On phones menus still ran under the top bar or the tab bar or out of the page's scrolling area, and a long menu did not show its chosen item; #475 measures the room between the bars and inside every clipping box, opens toward the larger side and scrolls the chosen item into view. v3: `uiPicker` clamps automatically, `uiPickerBounds`, `uiPickerPlace`, `uiPickerReveal`; utils.js:2672-2754, 2759-2773, 2817-2828, 2909-2926; ui.css:329-333, 598, 693-694, 747-749, 964-967, 1866-1868, 1933-1934, 2555, 3084-3109.
- **MP-6 Filter bar: rare filters behind a Filters button with a badge.** A filter bar shows the search and the common pickers; less used filters hide behind a Filters button, the funnel icon Messages uses, shown at every size in a filter bar (`.ui-fbar .ui-filters-toggle { display: inline-grid }`; `.ui-fbar-more` from `none` to `grid` with `auto-fit minmax(180px, 1fr)` once the bar is `.is-open`). The icon button has no fill: a square the height of the search (`var(--ui-ctl-h)`, 34px) with a 1px line border, which turns ink with the icon while open (`aria-expanded="true"`), the same frame as the Sort button beside it (TB-28), so Sort and Filters look alike. Opening it moves focus to the first revealed field and the button stays marked. If hidden filters are in use, the button shows how many in a small count on its corner (`.ui-msg-filter-n`, `position: absolute; top: -6px; inset-inline-end: -6px; min-width: 18px; height: 18px`, accent background, hidden at 0) and its name says it ("Filters, 2 in use"). "Clear filters" appears only when something differs from its start value, and clearing puts each filter back on its own default, which may not be All. Changed means: text non-empty after trim; select differs from `defaultSelected` or the first option; checkbox differs from `defaultChecked`; `data-filter-default="x"` differs from x; hidden, date and datetime-local never count; `data-no-filter` never counts. Phones: search `flex-basis: 100%`, or `flex: 1 1 0` beside a Filters or Sort button so they share one line; the rest open two to a line. Screen reader: toggle `aria-expanded`, `aria-controls`, `aria-label` and `title` "Filters" or "Filters, N in use". Example: suppressions default to "Active Only" and Clear returns there. Pitfall: #260 kept the Messages search, Apply and Clear visible with the other filters behind a Filters button, #285 moved sender, recipient, user and IP from a folded section at the foot of the sidebar to a button next to the search, #425 extended it to Spam Filter and Mailbox Stats, #432 made it the shared filter bar, and #475 turned the "Filters" text buttons of Security events, the mail queue and Mailbox Stats into the funnel icon Messages uses. v3: `uiToggleFilters(this)` inside `.ui-filters`, `uiFilterChanged`, `uiFilterBarSync`; utils.js:1887-1895, 1909-1965; ui.css:569-576, 2574, 3068-3070, 3079; index.html:825, 889, 1222; app.js:4519-4561.
- **MP-7 Row menu on the native popover layer.** A row's "..." button opens a small menu built on HTML `popover` + `popovertarget` (light dismiss and Escape native), so the table's own scrolling never clips it: `position: fixed; inset: auto; min-width: 150px`, padding 4px, shadow `0 8px 24px rgba(0,0,0,.14)`, items `7px 10px`, focus and hover `ink 7%` (hover only where a pointer can hover, `@media (hover: hover)`). It opens under the button with a 4px gap aligned to its end edge (alignment read from the button's computed `direction`, so it mirrors in RTL), flips above when there is no room and is clamped 8px inside the viewport. A capture-phase scroll listener closes it rather than letting it drift; any choice closes it; a click outside closes it. Non-popover panel: `position: absolute; top: calc(100% + 4px); inset-inline-end: 0; z-index: 40; min-width: 170px`. Screen reader: button `aria-haspopup="menu"`, panel `role="menu"`, items shaded on `:focus-visible`. v3: `uiMenu(label, itemsHtml)`, `uiInitMenus()` once at startup; utils.js:388-415; ui.css:1543-1548, 1981-1987; index.html:918-925; spam_filter.js:1136-1196.
- **MP-8 Period picker with presets and a custom range.** Offer presets All Time, Today, Last 7 / 30 / 90 Days (chips "7 Days" and so on, labels "Last 7 Days"), and a custom range; All Time sends no dates. Days are days in the app's time zone: Today starts at its midnight, and Last N Days is the last N x 24 hours (the same window as Mailbox Stats, also across a daylight saving change; the Dashboard's periods are bars cut at the app zone's clock, CH-1). A preset updates the label, marks its chip, closes the picker and reloads; on Messages each chip shows its count, like the facets. Opening pre-fills the custom range with the range in use (`onOpen` hook); Mailbox Stats fills the last 30 days when it is empty. A custom range needs both dates with start before end, otherwise a toast "Please select both start and end dates" or "Start date must be before end date" (`warning` on Messages, `error` on Mailbox Stats). The range is whole days in the app's zone, from the first day's start to the last moment before the day after the last one (`zonedDayStart(addDaysToDateString(end, 1)) - 1`, 23 or 25 hours on a DST change), and the button label names the days as picked ("01/10/2026 - 16/10/2026", `formatDayKey(day)`). In the narrow facets column the custom range opens inline as a section (`position: static; width: auto; box-shadow: none`). Keyboard: preset chips use `aria-pressed` (a custom range presses none); closing returns focus to the button. v3: app.js:4567-4688, 4744-4750; utils.js:498-534; mailbox-stats.js:577-623; ui.css:342-345.
- **MP-9 Facets as toggle lists on wide screens, picker buttons where they hide.** On wide screens the Messages outcome (All, Delivered, Deferred, Bounced, Rejected, Spam, Discarded (Sieve)) and direction (Any, Inbound, Outbound, Internal) are lists of toggle buttons with a colored dot and a count; clicking one applies at once, closes any open picker and reloads. Below 1280px the same lists open from three buttons (Outcome, Direction, Time), one at a time, each naming the choice in use and drawn dark when set (`.is-set` on `#messages-<kind>-pick`; Time is set when a start or end date exists). Render one option list and one set of functions either as toggles or as picker options; hidden status and direction selects stay the single source of the filter. Screen reader: facet buttons use `aria-pressed`; in a picker the same choices are its options. Pitfall: the outcome showed as a sideways-scrolling strip of chips and the direction did not show at all (#343); #342 made the range label a button, #431 moved all three onto the shared picker, and #268 kept the hidden selects as the single source so the Dashboard quick search still works. v3: app.js:4694-4766.
