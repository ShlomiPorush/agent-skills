# UI behavior rules (v3 style): Dialogs and sheets

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `0210d15` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Dialogs and sheets

- **DS-1 Phone sheet opens at four fifths and grows with the scroll.** On phones (`max-width: 760px`) every centered dialog, and every help or release-notes text, opens as a bottom sheet with rounded top corners at `max-height: 80vh; max-height: 80dvh`. Scrolling the content first raises the sheet by exactly the scrolled distance, smoothly, until it fills the screen; only then does the content scroll: on each scroll `grow = min(body.scrollTop, innerHeight - panelHeight)`, add `grow` to the panel height and subtract it from `body.scrollTop` so the text stays visually still, ignore growth under 1px. At full height square the corners and clear the notch (`border-radius: 0; padding-top: env(safe-area-inset-top); transition: border-radius .2s ease`). Head, message header and tabs keep their size (`flex-shrink: 0`), the body gives way (`flex: 1 1 auto; min-height: 0`). Catch every inner scroller (body, tab panel, nested list) with one passive capture-phase scroll listener on the backdrop. Wide screens keep the centered dialog. Pitfall: the first version jumped to full screen on any scroll; growing by the scrolled amount fixed it (#353), and #428 moved the start from three quarters to four fifths and made every dialog a sheet so phones have one kind of popup. Use `dvh` with a `vh` fallback; create the dialog watcher only where `MutationObserver` and `document.body` exist, because tests load the script without a page. v3: `uiSheetShow(id, { expand: true })`, `uiDialogSheet`; utils.js:1346-1361, 1544-1570, 1624-1640; ui.css:850-853, 2763-2778.
- **DS-2 Bottom sheet primitive.** A panel rises from the bottom over a `rgb(0 0 0 / .4)` veil, sized to its content up to `max-height: 88vh; max-height: 88dvh`, `border-radius: 16px 16px 0 0`, shadow `0 -8px 30px rgb(0 0 0 / .2)`, layer `position: fixed; inset: 0; z-index: 70` with `justify-content: flex-end`. Grip and head stay fixed; only the body scrolls (`overflow-y: auto; overscroll-behavior: contain; padding: 12px 16px calc(20px + env(safe-area-inset-bottom))`), so reaching its end never scrolls the page behind. Inside, long words wrap (`overflow-wrap: break-word`), `pre` and tables scroll sideways in place (`display: block; max-width: 100%; overflow-x: auto`) and images shrink (`max-width: 100%; height: auto`). Screen reader: panel `role="dialog" aria-modal="true" aria-label`, grip `aria-hidden`, close button `aria-label="Close"`. v3: `uiSheetShow(id, { label, head, body, expand, progress, onClose })`, `uiSheetDismiss(id)`, `uiSheetClose(id)`; utils.js:1324-1366; ui.css:845-870.
- **DS-3 Drag to grow, pull down to close, with spring back.** Dragging the grip or the fixed top part (head, message header, tabs) upward lifts the sheet with the finger toward full screen (`height = min(innerHeight, startHeight - moved)`, `transition: none` during the drag so it tracks 1:1). Pulling down moves it with the finger; released past `min(120px, panelHeight / 4)` it slides off (`transition: transform .2s ease; translateY(100%)`, dismissed after 200ms), released earlier it springs back with the same `.2s ease`. From inside the content a downward pull moves the sheet only when the content and every scroller between the finger and the sheet is at its top (any ancestor with `scrollTop > 0` cancels the gesture); an upward drag from the body never grows the sheet. All touch and scroll listeners `{ passive: true }`. Touch only: with a mouse the sheet does not drag, and backdrop, X and Escape still close it. Pitfall: a pull from the content must not fight the content's own scroll. A dialog closes only through its own Close button (`aria-label="Close"` in the head) so the owner's cleanup and its Back history entry run; a dialog without one can grow but cannot be pulled shut. Reset the transform after closing so the dialog reopens normally (#351, #428). v3: `uiSheetSwipe`; utils.js:1415-1450, 1572-1622.
- **DS-4 Grip: small line, large hit area, bolder while held.** A short line at the top of every sheet: drawn `40px x 4px` in `--ui-line` (centered gradient) inside a `120px x 20px` hit area with `margin-bottom: -4px`. While a finger holds the grip or the fixed head it becomes `56px x 5px` in `--ui-ink` (`transition: background-size .15s ease`) and returns when released: add `.is-held` on `touchstart`, remove it on `touchend` and `touchcancel`. Cursor `grab` and `grabbing` on desktop. Decorative: `aria-hidden="true"`, no keyboard role. Pitfall: the plain handle was too small to catch; #428 added the large hit area and the held state. Without `touch-action: none` on the grip the browser takes the drag for a page scroll. v3: `.ui-sheet-grip`, `.ui-dialog::before` with `.ui-dialog.is-held`; utils.js:1340, 1416, 1422, 1438; ui.css:854-857, 2769-2771.
- **DS-5 Reading gauge in the popup header.** In an information sheet or dialog (help, changelog, release notes) the whole top area, grip plus head, fills from the start side with a faint accent tint as the reader scrolls: empty at the top, full at the end. Width `scrollTop / (scrollHeight - clientHeight) * 100%`, capped at 100; height `head.offsetTop + head.offsetHeight`, measured on each update; fill `color-mix(in srgb, var(--ui-accent) 16%, transparent)`, `transition: width .08s linear`. Hide it when the scrollable room is 1px or less, so a text that does not scroll shows no gauge. The host gets `position: relative; isolation: isolate` so the bar sits at `z-index: -1` behind the head content but not behind the panel; bar `position: absolute; inset-inline: 0; top: 0; overflow: hidden; pointer-events: none`, inheriting the top corner radii. Recompute once more on the next animation frame after opening; attach one listener per scroller. `aria-hidden="true"`; `inset-inline` makes it fill from the right in RTL. v3: `uiReadProgress(headEl, scrollerEl)`, `uiSheetShow(..., { progress: true })`; utils.js:1368-1394; ui.css:2780-2786; app.js:4990-4997.
- **DS-6 Every opening starts fresh; closing cleans up.** Each time a dialog or sheet opens it starts at the top of its content (on a phone at 80% again), on its first tab, never where a previous text was left. On each opening of a phone dialog sheet clear the inline height and transform, scroll every `.ui-dialog-body` to 0 and remove `is-grown`/`is-full`; attach its listeners once (`data-sheet`). For a shared info dialog set `body.scrollTop = 0` after `classList.remove('hidden')`. Closing clears what belonged to that opening: the open item key, the selected row mark, the scroll lock, pending searches and late answers. Example: Manage Reports resets search and sort on every opening, and on close cancels its search timer and dim and bumps its request counters so late answers cannot repaint a closed dialog. Pitfall: help, changelog and update notes share one dialog, and each opened with the new text but kept the scroll position of the one before, so a help page could open in its middle (#374); #428 made every phone sheet start at the top. A hidden element cannot be scrolled, so reset after it is shown. v3: utils.js:1550-1556; app.js:4988-4996; message-details.js:54, 115-139, 873; dmarc.js:1119, 1276.
- **DS-7 A redrawn sheet keeps its place.** When a page redraws an open sheet with new data it does not jump to the top or shrink: restore the previous `.ui-sheet-body.scrollTop`, and keep a grown height in `sheet.dataset.height` and reapply it, so a sheet the user grew stays grown. The sheet stays open through the page's own refresh. Example: the Security address sheet redraws on the 30s refresh and closes by itself when the address leaves the list. v3: `uiSheetShow` called again with the same `id`; utils.js:1322-1345, 1350.
- **DS-8 Escape closes the top layer only.** One owner decides: a window-capture Escape handler (router.js) closes only the top layer, ordered by z-index and then page order, through its Close or Cancel button, and stops the event, so no listener of a layer underneath sees it. It yields to a picker or an open popover inside the top layer and to the phone search, which close themselves. No dialog has its own Escape listener; the docked reading pane, which is not a layer, still closes on Escape when no layer is open. Focus moves into a layer when it opens (its first field, but not on a touch screen, where it would raise the keyboard; else its primary button; else the panel), returns to the control that opened it (a window that opens after a request names its opener before the request), and falls back to the layer below or the page heading. Everything beside the path from the page to the top layer is `inert`, except toasts and, beside the phone More sheet, the tab bar; `aria-modal` is set only while the element is a layer. Every layer closes this way, through its own Close or Cancel: confirmations, the record window, alert activity, the message dialog, sheets. A picker's Escape (capture phase) closes only the picker and returns focus to its button; an open row menu closes on the native popover's Escape. Back follows DS-10. Helpers: `openOverlays`, `closeTopOverlay`, `layerChildOwnsEscape`, `syncLayerFocus`, `uiLayerOpener` in router.js. Before the interaction fixes (history; where it differs from the text above, the text above is the rule): Escape closes only the topmost thing: an open picker inside a dialog closes before the dialog, the global search closes without closing a dialog under it, and with several sheets the last `.ui-sheet` in DOM order closes. Confirmations, the record window, alert activity and sheets all close on Escape. Nested layers listen in the capture phase and call `stopPropagation` (the picker's keydown in the capture phase, the search with `stopPropagation`); the confirm has its own listener; row menus use the native popover's Escape; Back follows DS-10. A picker's Escape returns focus to its button. Pitfall: before #431 the Messages pickers did not close on Escape; #431 listens in the capture phase "so Escape closes the picker before it reaches a dialog or sheet under it". #278 made the shared confirm close on Escape, and #385/#387 did the same for the record window. v3: router.js:328-375, 392-510; utils.js:1848-1866, 751-752; search.js:595-599.
- **DS-9 Backdrop and close rules per dialog kind.** The rule holds for every window: a click outside closes a window without typed input (the container log, rule test results, quarantine details, alert activity, mailbox activity, the DMARC record, fetch history, a connection test, Block details, a confirmation as Cancel) and never one with typed input (Basic Auth verification, Manage Reports with its search, every edit dialog). A click inside a dialog never closes it: the backdrop handler checks `event.target === this`, and the message dialog and the suppression dialogs stop propagation from `.ui-dialog`; the suppression add and edit dialogs have no backdrop handler and are removed from the DOM on close. A typed dialog (quarantine rule, notification destination, suppression add and edit) asks "Discard your changes?" with [Keep editing] then [Discard] on screen, focus on Keep editing, when Close, Cancel, Escape or Back would drop a field that differs from how it opened; a save closes it without asking and closes a question still open for it. A connection test window is one at a time, and a reply for a closed or older test is dropped. A sheet closes on a backdrop tap, X or Escape, and the page that opened it can run its own close logic: `onClose` replaces the default removal and usually ends with `uiSheetClose(id)`. Helpers: `uiGuardDialog`, `uiCloseGuarded`, `uiCancelDialog`, `uiDialogSaved` in utils.js. Before the interaction fixes (history; where it differs from the text above, the text above is the rule): Windows that show information close on a backdrop click and on Escape; small edit dialogs with typed input stay open on a backdrop click and close by Cancel or X; a click inside a dialog never closes it. Backdrop handler `onclick="if (event.target === this) close...()"` on alert activity, mailbox activity and DMARC record, backdrop close also on fetch history and Manage Reports; Escape on DMARC record, mailbox activity and message details; the message dialog stops propagation from `.ui-dialog`; suppression dialogs use `onclick="event.stopPropagation()"`, have no backdrop handler and are removed from the DOM on close. A sheet closes on a backdrop tap or X, and the page that opened it can run its own close logic: `onClose` replaces the default removal and usually ends with `uiSheetClose(id)`. v3: `uiSheetShow(..., { onClose })`, `uiSheetDismiss(id)`; index.html:1617, 1627, 1662; utils.js:1338, 1341, 1396-1408; app.js:4999-5009, 5171-5187, 3418-3427, 3505-3513; dmarc.js:584-586, 1051-1057, 1122; mailbox-stats.js:438-440; message-details.js:892-921; spam_filter.js:757-767, 794-809; app.js:3096; utils.js:800-844.
- **DS-10 Back closes the top overlay instead of leaving the page.** With a dialog, a sheet (phone help, an address), the logs dialog, the phone More menu or the phone search open, the browser Back button or phone back gesture closes the top one and stays on the page; with two overlays each Back closes one, and a jump of several steps back closes every open one. While anything is open hold one extra history entry at the same URL with `state.overlay = true`, kept in sync by a body `MutationObserver` (class changes and added nodes) batched per animation frame; a layer marked `data-no-history` (the "Leave without saving?" question, which is also asked during Back and Forward) adds none. To close the top overlay look in it for `[aria-label="Close"]`, `[id$="-cancel"]`, `[data-cancel]`, a button whose text is Cancel/Close, a button whose `onclick` starts with `close`, else send a synthetic Escape; the More menu uses `closeMobileMenu()`. Give each overlay such a Close button so Back runs its own close logic (the confirm is cancelled by Back through `#app-confirm-cancel`, a choice dialog through `[data-cancel]`, and a typed dialog asks first, DS-9). Closing by hand calls `history.back()` and ignores the resulting popstate, so the next Back really leaves the page; navigation from inside a dialog replaces the overlay entry (`routerReplace`, `replaceState`), so no stale dialog step is left behind. Order the open layers by z-index, then page order (DS-8): the phone search drops below a message it opened, so the message counts as on top; exclude `.ui-dialog-backdrop.ui-docked`. Pitfall: on a phone, Back with a message open went to the previous page and left the message behind (#312), and Back left the page behind the full-screen phone search instead of closing it (#383). Overlays open by class change or by insertion, so watch both, and decide the stacking order explicitly. v3: `OVERLAY_SELECTOR`; router.js:299-540, 278-286, 310-312, 317-332, 522-528, 641-669, 704-708.
- **DS-11 Scroll lock behind overlays.** While a dialog or sheet is open the page behind stays still: `body.ui-sheet-on { overflow: hidden }`, released only when the last sheet closes; dialogs set `document.body.style.overflow = 'hidden'` and restore `''`. In an app-frame layout lock every scroll region, not only body: with Message Details open as an overlay, `html:has(#message-modal:not(.hidden):not(.ui-docked))` sets `overflow: hidden !important` on html, body, `.ui-page`, `.ui-scroll`, `.ui-gs-body`, `.ui-sidenav`. The dialog's own scroll never chains outward and its last line clears the phone home bar: dialog sheet body `overscroll-behavior: contain; padding-bottom: calc(var(--ui-pad-x) + env(safe-area-inset-bottom))`. A dialog blocks the page behind it; a docked reading pane does not. v3: `uiSheetShow` handles `ui-sheet-on`; utils.js:1364, 1407; ui.css:876, 2522-2526, 2777.
- **DS-12 Styled confirmation dialog.** Destructive or important actions ask in a small fitted in-app dialog with a title, a message and two buttons instead of the browser's confirm(); newlines in the message become line breaks, the text is escaped, and a second confirm replaces the first. The confirm button takes focus after `100ms`, so Enter confirms; Escape (through the layers, DS-8) and a click outside cancel (resolve false). A question that protects changes ("Leave without saving?" [Stay] [Leave], "Discard your changes?" [Keep editing] [Discard]) starts on its safe answer instead (`focusCancel: true`), and the Leave question writes no history entry of its own (`noHistory: true` sets `data-no-history`), since it is also asked during Back and Forward. A dangerous action (`isDangerous: true`) gets a solid red `ui-btn-danger-solid` button, otherwise `ui-btn-primary`, with optional `confirmColor`. A question with more than two answers uses the same frame through `showChoiceModal`: Cancel first, then one button per choice (`kind` primary, danger or plain), focus on Cancel after `50ms` so Enter never picks a destructive choice, Cancel, Escape and a click outside resolve `null`, and a second one closes the first as cancelled (example: "Keep this app's Rspamd blocks?" [Cancel] [Keep blocks] [Remove blocks]). It appears above any dialog it was opened from with only toasts above it (`.ui-dialog-backdrop.ui-confirm { z-index: 99999 }`, toasts at `100000`) and locks the page (`body.style.overflow = 'hidden'`). On phones it is a sheet without a head Close, so it cannot be pulled shut, and Back cancels it (`#app-confirm-cancel`, `[data-cancel]`). Screen reader: `role="alertdialog"`, `aria-label=<title>`, `aria-modal` set by the layers; the choice dialog also has `aria-modal="true"` and `aria-describedby` on its message. Example: settings use `role="alertdialog"` for disabling a feature and `role="dialog"` for verifying credentials. Pitfall: the confirm was always dark whatever the theme; #278 made it follow the theme and close on Escape. v3: `await showConfirmModal({ title, message, confirmText, cancelText, confirmColor, isDangerous, focusCancel, noHistory })` resolves true or false; `await showChoiceModal({ title, message, choices: [{ value, label, kind }], cancelText })` resolves the chosen value or null; utils.js:707-798, 899-913; ui.css:2102, 2090; settings.js:54-56, 149-151, 725-729.
- **DS-13 Docked reading pane on wide screens, dialog elsewhere.** On the Messages page on a wide screen (`matchMedia('(min-width: 1000px)')` matches and `currentTab === 'messages'`) a message opens as a third column beside the list, like a mail client: no dialog head, no shadow, the clicked row highlighted, and the first message opens by itself when the list loads (when a reader slot exists, the dialog is hidden and the list is not empty). Everywhere else, and on narrower screens, the same element is a dialog and the page behind is locked. Docked form: `#message-modal.ui-docked { position: static; display: block; height: 100% }`, dialog `border: 0; border-radius: 0; box-shadow: none`, head hidden, header padding `30px 36px 0`, body `20px 36px 60px`; hide the "Select a message" hint with `.ui-reader:has(#message-modal:not(.hidden)) .ui-reader-empty`. Use one element that moves between forms so every id and handler stays; as a dialog it moves to the end of body, so it opens over any dialog already open (Block details opens a message from its own dialog) and Escape closes the message first, and exclude docked dialogs from sheet, drag, scroll lock and Back history logic. Auto refresh keeps running while docked and pauses while it is a dialog. Pitfall: #261 paused auto refresh whenever a message was open "so the list does not re-render under the reader"; #268 kept it running for the docked form (a dialog still pauses it) and opened the first message in the pane. v3: `.ui-docked`, `messageReaderSlot`, `placeMessageModal`; message-details.js:19-42, 95-98; spam_filter.js:765-766; app.js:3991-4000; ui.css:560, 562-570, 2523-2525; utils.js:1557; router.js:310-312.
- **DS-14 Sticky heads inside a scrolling dialog stick at the visible edge.** In the Logs tab of a message the timeline title and its filters stay pinned while entries scroll, flush with the visible top of the pane, with no log line peeking above them, both in the dialog and in the docked pane: `position: sticky; top: 0; z-index: 2; padding: 6px 0; background: var(--ui-bg)`; inside a dialog body `top: calc(-1 * var(--ui-pad-x))` (minus the body's 16px top padding); docked `top: -20px`; `.ui-md-fill:has(.ui-md-timeline) { height: auto }`. Set the sticky `top` to minus the scroller's top padding. Pitfall: the message body scrolls with top padding, so the sticky head stopped below it and log lines showed through above the head (#291); a scrolling container's top padding offsets every sticky child by that padding. v3: ui.css:442-451.
- **DS-15 Dialogs live at body level.** A dialog is never hidden behind page content or sticky bars: append dialogs to body, outside the app content (the container log dialog sits outside `#app-content` as a child of body, Tailwind `fixed inset-0 z-50`, `max-h-[85vh]`). Pitfall: the container log dialog lived in the sidebar, whose sticky position made a stacking context, so the sticky Settings search showed above it (#290); `position: sticky` creates a stacking context, and a dialog inside it cannot rise above other sticky content whatever its z-index. v3: index.html:1539-1578.
- **DS-16 Centered dialog: fixed head, scrolling body, content-sized variants.** A dialog opens centered over a dark veil; its head stays put and only its body scrolls. Backdrop `position: fixed; inset: 0; z-index: 50; padding: 16px; background: rgb(0 0 0 / .45)`; dialog `width: min(1100px, 100%); height: 90%`, flex column, shadow `0 24px 60px rgb(0 0 0 / .25)`; body `flex: 1; min-height: 0; overflow-y: auto`. Short dialogs shrink to their content and widths fit the task: `.ui-dialog-fit` `height: auto; max-height: 85vh`; `.ui-dialog-sm` `min(460px, 100%)`; `.ui-dialog-md` `min(680px, 100%)`; DMARC record `min(760px, 100%)`; alert activity `min(940px, 100%)`. A tab strip inside shares the width but scrolls sideways on narrow screens and labels never wrap: tabs `overflow-x: auto`, tab `flex: 1; min-width: max-content; white-space: nowrap`, active accent underline; page tabs `flex: 0 0 auto; margin-inline-end: 18px`. Screen reader: `role="dialog"` with `aria-label` or `aria-labelledby`; close buttons `aria-label="Close"`; page tabs use tablist/tab/tabpanel with `aria-selected`. v3: `.ui-dialog-backdrop > .ui-dialog > .ui-dialog-head + .ui-dialog-body` plus a size class; ui.css:383-398, 1629, 1636, 1641-1642, 1784, 1944, 2645, 2709; index.html:1494, 1507-1512, 1521, 1603, 1617, 1627, 1637, 1662.
- **DS-17 Dialog opens at once with Loading, then fills in.** A details or record window opens immediately with its title and "Loading..." with a spinner, then fills in place; any old copy is removed first, and a failure is shown inside the same window with the reason. Open the shell first, then fetch and fill its body. Quarantine details: built as `.ui-dialog-backdrop > .ui-dialog.ui-dialog-fit`, "Loading details...", "Failed to load details" plus the reason. Record window titles "DMARC record · example.com", "TLS-RPT record", "SPF", "DKIM"; failure "Could not read the record: ...". Screen reader: `role="dialog"`, `aria-label="Quarantine Item Details"`; record window `aria-labelledby="dmarc-record-title"`. v3: app.js:3087-3132; dmarc.js:568.
- **DS-18 Dialog actions close the dialog first, then act.** Pressing an action inside a dialog closes the dialog first, then runs the action (with its usual confirmation) or navigates, so the user lands on the result without a stale window behind; call the dialog's close first in each action handler. Quarantine footer order: Spam, Not Spam, gap (`.ui-toolbar-gap`), Delete (danger), Release (primary). Alert activity: for a volume spike or an SMTP block by abuse protection, "Open in Messages" filters by the mailbox that logged in (`filterType: 'user'`, whichever address or alias it sent from); for an auth failure burst, "Open in Security" clears IP, action and country filters, sets the username and opens Events; the filter is applied `100ms` after the navigation, and only when the move happened (Stay on an unsaved-changes question cancels it); "Dismiss the alert" (primary) appears only when not acknowledged. Mailbox activity "Open its messages" and the DMARC record's sender rows close their window first the same way. The alert activity window closes on Escape through the layers (DS-8) and on a click outside. v3: app.js:3207-3216; alert-activity.js:12-43, 189-209; dmarc.js:715; app.js:66-69; mailbox-stats.js:434.
- **DS-19 One shared frame for help, changelog and release notes.** Help, changelog and release notes share one dialog in the app frame and font (a sheet on phones) that follows the app theme, not the operating system (markdown `color-scheme: inherit` with GitHub variables mapped to tokens). Markdown callouts (NOTE, TIP, IMPORTANT, WARNING, CAUTION) render as colored boxes with a `3px` start border and `8 to 9%` tint; lists keep their bullets (sheet lists `ul disc`, `ol decimal`, nested `circle`, `square`); if the Markdown library fails the text still shows, escaped. Every page title has a help button (`ui-help-btn`, title "Help - <page>") that opens its page of the documentation; the window opens once the text has loaded and focus returns to that button (`uiLayerOpener`). Inside the app a help page leaves out its screenshots (the page itself is on screen), its relative links and links to its own sections point to the documentation site, and every link to another site opens in a new tab (`target="_blank" rel="noopener noreferrer"`); in dark mode links and callout titles keep their colour. A help page that fails to load opens the same container with a plain error, "Failed to load help documentation. Please try again later." (phone sheet without expand or progress). "Read changes" and update badges open the changelog where the user is. Titles: help "Help - <title>", the page's own name when it passes one ("Help - Outgoing spam" for `Abuse_Protection`), else the file name read as words ("Help - Mailbox Stats" from `Mailbox_Stats`); updates "Update Available: <name>", "mailcow Update: <version>", "Update: v<latest>"; missing changelog "No changelog available". Pitfall: following the operating system's theme showed dark tables in light mode (#285). The phone sheet showed changelog and help lists without bullets because the reset clears list markers and only the desktop dialog restored them, so restore bullets in every new container (#362). The app update alert's Read changes went to the About page while the mailcow alert opened its changelog (#362). v3: `showHelpModal(docName, title)`, `helpDocMarkdown`, `showMarkdownModal`, `renderMarkdown`, `markdownCallouts`, `.markdown-body`; utils.js:339-373; app.js:969-1006, 1044, 4327, 4350-4359, 4975-4983, 5194-5262; about.js:172-189; ui.css:871-875, 2179-2209; index.html:163-178, 592.
