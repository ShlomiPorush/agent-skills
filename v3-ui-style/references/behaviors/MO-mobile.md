# UI behavior rules (v3 style): Mobile

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `72e43c4` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold. A sentence that starts "Before the auto-refresh layer" or "Before #509" describes older code in the same way: history, not the rule.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Mobile

- **MO-1 The phone keyboard resizes the app; the window pan is reset.** When the phone keyboard opens, the layout shrinks to the visible area instead of being covered: `<meta name="viewport" content="... interactive-widget=resizes-content">` on the app and login pages, combined with `dvh` units. After the keyboard closes the page snaps back to the top so the top bar is not hidden and no empty band remains: reset the window pan on window `scroll`, on `focusout` after 300ms and on `visualViewport` resize after 100ms, and skip the reset while focus is in an input, textarea, select or contenteditable, so the page never moves while a field is being edited. Pitfall: before #311 the app could stay shifted after the keyboard closed, on every page, with the top bar off screen and an empty band at the bottom. `scrollIntoView` also scrolls the app frame and can pan the window; scroll the page's own area instead. v3: `resetWindowPan`; index.html:6; login.html:5; app.js:6533-6548; ui.css:911-915, 1062, 2429, 2431.
- **MO-2 Form fields are 16px on phones.** Fields (inputs, selects, textareas) use `font-size: 16px` at 760px and below and in the phone search sheet, so focusing a field on iOS does not zoom the page. v3: ui.css:372-373, 2839.
- **MO-3 Safe-area insets everywhere something touches an edge.** Nothing hides behind the notch or the home indicator: add `env(safe-area-inset-*)` to every edge-touching fixed element, namely the tab bar height and bottom padding, content bottom padding, More sheet bottom, save bar bottom, sheet body bottom, dialog sheet body bottom (or its foot, when it has one), the message details content bottom, full sheet and full dialog top, phone search top and body bottom. v3: ui.css:916, 925, 1276-1279, 1290, 2270, 2481, 2837, 2847, 3118-3124.
- **MO-4 Hover only where there is a pointer.** Wrap hover colors in `@media (hover: hover)` so a tapped navigation item on a touch screen does not stay grey (nav hover `side-ink 8%`). Controls answer the pointer quietly: `.ui-btn:hover` muted border, `.ui-icon-btn:hover` `ink 7%`, `.ui-server:hover` 9%, `.ui-fct:hover` `ink 6%`, `.ui-md-spam:hover` solid, `.ui-log-svc:hover` and `.settings-edit-tab:hover` `ink 7%` background, `.ui-bl-link:hover` and `.ui-gs-tab:hover` text in `ink`, `.ui-tag-btn` `cursor: pointer`. Every hover rule is gated this way: in ui.css, in the page's own style block, and in the Tailwind utilities (`future: { hoverOnlyWhenSupported: true }`). A rule that mixes `:hover` with `:focus-visible` is split so the focus part stays ungated, at the same place in the cascade. A tooltip that is the only way to read a value stays ungated, so a tap shows it: the DMARC day columns (`.ui-dm-col:hover::after`), and a message's relay (Logs tab strip and recipient rows), which shows its host with a small port chip and the server's IP in a tooltip ("IP 192.0.2.1"; for a host cut by its width "<host> · IP <ip>", so the tooltip names it in full). The relay's tooltip shows on hover, on keyboard focus (the strip's host is focusable; a focused recipient row shows its relay's) and on a tap on a touch screen (`pointerType` not `mouse`), where it stays `2500ms` (`.is-tip`); the click that follows such a tap within `600ms` belongs to the tooltip, so a tap on a row's relay does not open the row, while a mouse click or a later tap does. A host with a tooltip has a dotted underline; screen readers read ", IP <ip>" as hidden text. Pitfall: without the gate a tapped item stayed grey on touch screens; #279 kept hover colors to pointer devices, and the interaction fixes extended the gate from the navigation to every rule. v3: `mdRelayTip`, `mdRelayTipTap`, `mdRelayTipFit`, `mdRelayTapped`; ui.css:167, 433-438, 549, 646-650, 1047, 1196, 1210-1211, 1235, 1697-1698, 1730, 2339, 2799, 2947-2948; message-details.js:472-524, 836.
- **MO-5 Touch targets.** Phone targets are easy to hit: tap targets at least 44px (`.mobile-menu-item { min-height: 44px }`), sheet grips `120px x 20px`, tab bar 64px tall, phone search box 46px. v3: ui.css:918, 1278, 1297, 2838, 3111.
- **MO-6 Phones leave out what the page already says elsewhere.** On a phone hide only what another visible element repeats: the DMARC mail flow diagram ("the Senders table under it says the same"), the country bars' tracks and the Security side column (`.ui-dm-flow-card`, `.ui-sec-bar-track`, `.ui-sec-two > .ui-sec-side` `display: none` at 760px); Daily reports start folded; hints that only explain the page go. Actions that would sit beyond a table's scroll edge move into the detail ("a button beyond the scroll edge is a button nobody finds"), and tables keep natural widths and scroll inside their card (`.ui-dtable-scroll { overflow-x: auto }`) rather than squeeze addresses; on rate limits Limit, Last reset and Reset leave the sender table, Type and Queue id hide, and search goes full width. Some labels exist only on one form factor: `.ui-phone-only` inline at 760px, `.ui-phone-hide` hidden at 760px, `.hide-mobile` hidden at 640px, `.ui-ms-wide-only`. Phones get their own layout; wide screens stay unchanged. v3: ui.css:950, 978-979, 1836, 1986, 1997, 2017-2022, 2925-2928; index.html:75-79; rate-limits.js:413-417, 610-618, 697.
- **MO-7 One line per item on phones, details in a sheet.** At `max-width: 760px` each list item is one line (flag, address, tag, the sentence cut with an ellipsis on `.ui-sec-why`, row padding 9px); actions leave the row and a tap opens the details and actions in a bottom sheet, so the list stays where it was. A network ban row (`.ui-sec-row.is-static.is-net`) opens nothing, so it is the exception: its top line wraps, its sentence shows in full and its Unban stays in the row. The four list filters sit two by two (seg `grid 1fr 1fr`) so History is in sight without sideways scroll. The country chart and networks beside the list go away; Country and Network pickers in the filter row open the same data, and active filter chips are hidden because the picker shows the value. A row of protection pills folds into one chip ("Protection 4 of 5 on" with a chevron, `rotate(45deg)` -> `rotate(-135deg)`) that lists every protection in a column (`flex-direction: column`) when tapped. Keyboard: summary chip `aria-expanded`. v3: `uiSheetShow` from the row tap, `renderSecuritySheet`; security.js:34-35, 69, 289-297, 431-441, 450-473, 616-623, 777-785; ui.css:940-973.
- **MO-8 Figures two to a line; an odd last figure takes the whole line.** Figure strips go two per line on phones and an odd last figure spans the line instead of half (`div:last-child:nth-child(odd) { grid-column: 1 / -1 }`), with borders recomputed per position; facts strip values 15px; detail pages put each name beside its value. v3: ui.css:3019-3028, 3096-3099.
- **MO-9 Facts keep their name beside the value; compact phone rows.** On phones each fact sits on one line, name at the start and value at the end (fact grid `minmax(0, 1fr) auto`); a short note stays on the value's line, prefixed `· ` ("0 B / 1.0 GB · 0% used"); a mailbox's message count joins the quota line. Mailbox rows show the address with the activity sparkline pinned in the top corner (`position: absolute; top: 8px; inset-inline-end: 16px`, address `padding-inline-end: 124px`), storage and aliases on a line under it, and the counts as two grouped lists (Traffic, Sent mail). An alias shows only its non-zero counts (`.is-zero` hidden); a tap opens all of them (`.is-open` shows `.ui-ms-alias-more`), the chevron turns `rotate(90deg)`, and opened aliases stay open across re-renders (kept in memory). Other rows reflow: stats 4 -> 2 columns, message rows single column, identifier rows stack, container tiles min 150px. Keyboard: the alias chevron is a `<button>` with `aria-expanded` and `aria-label="All counts of <alias>"`; group headings are `h5`. Pitfall: #433 took several passes to keep each check's name beside its result, a mailbox's quota and its share on one line, the message count on the quota line, and a domain's counts with their notes on one line; wide screens keep the table and the row of tiles. v3: `mailboxStatsCache.openAliases`; ui.css:374-376, 695-697, 1002-1008, 1736-1744, 1828-1840, 1951-1975, 2420, 3032-3037, 3101-3102; mailbox-stats.js:414-429, 547-562, 586-607.
- **MO-10 Results as shapes, not color alone.** Meaning never depends on color alone. On a phone each DNS result in the domain list is an icon with its own shape (check, exclamation mark, cross) so it reads without color and three fit a line: icon 24 x 22px, 14px glyph, stroke 3; `.ui-tag` hidden, `.ui-dns-icon` shown; row `grid-template-columns: repeat(3, max-content minmax(0, 1fr)); gap: 6px 8px`, `.ui-dns-cell { display: contents }`; "Not checked" is "-". Wider screens show the word. Mailbox services that are off are struck through as well as greyed (`.ui-ms-svc.is-on`, off `text-decoration: line-through`). Screen reader: icon `role="img"` with `aria-label="SPF: OK"`; the inline label is `aria-hidden` so it is not read twice. Pitfall: #433 first showed each DNS result as an icon everywhere, then restored the words on wide screens and kept icons for phones only; render both forms and let CSS pick by width. v3: `dnsStatusTag`; domains.js:225-237, 277; ui.css:1815-1827, 1842-1849, 1922-1927.
- **MO-11 Long details become tabs on phones.** On a phone an open domain shows its details as two tabs (DNS checks, Details), one section at a time, with DNS checks first and open by default; wide screens show both. `.ui-domain-tabs` goes `display: none` -> `flex` at 760px; both sections are rendered and `data-tab="dns"` on the container hides `.ui-md-ids`, `data-tab="info"` hides `.ui-dns-section`; DNS grid 3 columns -> 1. The chosen tab is kept per domain in memory while the page is open, also after a single DNS check redraws the row. Keyboard: `role="tablist" aria-label="Domain"`, tabs `role="tab" aria-selected`. v3: `domainTabs[domainId]`; domains.js:13, 279-299; ui.css:1778-1786.
- **MO-12 A side list folds into one closed row on narrow screens.** Below 900px the Logs service list becomes one closed row naming the current service and its count; closed hides everything but the toggle. Tapping opens the list (`.ui-logs-side.is-open`, services grid `auto-fill minmax(150px, 1fr)`) with a turning chevron (`transform .15s ease`, open `rotate(180deg)`), and picking a service closes it again. The desktop sidebar is unchanged. Keyboard: toggle `aria-expanded`, `aria-controls="logs-service-list"`. v3: `toggleLogServices()`, `updateLogServiceToggle`; logs-viewer.js:134-162; ui.css:2333-2360, 2415-2418, 2449-2454, 2472-2474, 2567-2578; index.html:1333.
