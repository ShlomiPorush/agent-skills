# UI behavior rules (v3 style): Search

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `ab0f644` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Search

- **SR-1 One global search for pages, settings and data.** One search finds pages and each of their tabs ("Security > tab"), settings by visible name or by key (`dmarc_insights_window_days`) without the Settings page being open, messages, domains, mailboxes, suppressions and IP addresses. On wide screens it sits in the top bar on every page but Messages; on phones it opens from the search icon in the top bar on every page (SR-8). Build the index from the live navigation (visible `.ui-sidenav .ui-nav-item[id^="tab-"]` and the page's `[role="tab"]` buttons, badges stripped; `GS_PAGE_TABS` reads the tabs of Security, Quarantine, Outbound, Status and Mailbox Stats) and from the settings sections themselves, never from a copy. Hidden pages and tabs, and kinds of switched-off features, are not offered (each category's `feature` key checked against `window.disabledFeatures`, falling back to All if the current tab disappears). Settings is left out while settings cannot be edited in the app (`window.settingsEditable === false`), since a setting result opens its field; Suppressions only while the app keeps a suppression list (Sync with Rspamd on: `/api/suppressions/config` `list_kept`, read at most once a minute), otherwise the kind is not drawn at all. Settings whose name matches come before those matched only by key, which show the key. Query the IP list only when the text matches `/^[0-9a-f.:/]+$/i` (the slash for networks); banned and to-review are merged, newest first ("Banned · DE · 12 attempts"); a banned network opens the Banned list, an address its events (SR-6). Message results show the subject (or "(no subject)"), "sender -> recipient" and time ago. Suppression results show the address (a domain block by its domain), its state (Active, Inactive or Expired), reason and notes, and when it was added. Keyboard: see SR-4. Pitfall: #283 added a search inside Settings and #386 removed it because the top-bar search finds settings (two searches for the same thing was the rejected state); #382 replaced the Dashboard search box and its status filter with the one top-bar search, and reading names from the sections and tab buttons keeps them in one place. v3: `GS_CATEGORIES`, `GS_PAGE_TABS`, `settingsSearchIndex()`; search.js:9-17, 35-42, 58-62, 83-212; settings.js:1096-1109; app.js:625.
- **SR-2 Narrow until used, then widens; page buttons step aside.** At rest the top-bar search is a modest grey field (`flex: 0 1 300px; min-width: 42px`); focusing it widens it smoothly to most of the bar (`flex-basis: 820px`, `transition: flex-basis .22s ease`, at 761px and up with `html.ui-has-topbar`), and the box turns white with an ink border and a soft halo (`border-color: ink; background: --ui-bg; box-shadow: 0 0 0 3px color-mix(ink 10%)`, `transition: border-color .15s, box-shadow .15s, background .15s`), height 40px, input 15px with ellipsis, native cancel button hidden. A small "/" key cap shows inside while there is room and disappears once the user types (hidden at `@container (max-width: 150px)` and with `.has-q`; `aria-hidden`). Clicking outside closes the panel but keeps the typed text; leaving an empty field returns it to its narrow size; clicks inside a dialog or sheet (a message opened from search) are ignored. The next search starts again from All. Pitfall: the page's top-bar buttons wrapped when the search sat next to them; now the search gives way first and the buttons step aside while it is open (`.ui-topbar:has(.ui-gs.is-open) .ui-topbar-actions { display: none }`) (#382). v3: `.ui-gs` with `container-type: inline-size`, `.is-open`, `.has-q`; search.js:346-359 `gsOpen`, 569, 621-631; ui.css:2634-2654; index.html:423.
- **SR-3 Results panel: kinds as tabs with counts; All shows three of each.** Focusing the empty field shows nothing extra; the panel appears with the first character, right under the box and exactly as wide, never off screen: `position: absolute; top: calc(100% + 6px); inset-inline: 0; z-index: 45; height: min(560px, calc(100vh - 90px))`, grid `180px minmax(0, 1fr)` with a footer row, radius 14, shadow `0 22px 50px rgb(0 0 0 / .16)`. A side column lists the kinds (All, Pages, Settings, Messages, Domains, Mailboxes, Suppressions, IP addresses) with counts (`toLocaleString`, tabular): "..." while loading, "!" if failed, `opacity: .45` when zero; a kind with nothing to search right now (Suppressions while the app keeps no suppression list) is not drawn. All lists each kind with results under a heading "Messages · 1,204" (11.5px uppercase `.04em`), the first three (`GS_SUMMARY = 3`), and "See all" when there are more. A kind tab with a page behind it starts with a box "1,204 found · Open in Messages" ("Open in Mailbox Stats", "Open in Suppressions") that opens that page filtered by the query; kinds without such a box note "The first 10 of 57" (`GS_LIMIT = 10`). States: "Searching...", "Type one more character to search the messages, domains, mailboxes, suppressions and addresses too.", "This search failed. Try again in a moment.", "Nothing found for "query"", and a trailing "Still searching...". Highlight the first case-insensitive match of the typed text in titles and subtitles (`mark` `warn 22%`, radius 3). Each row: grid `22px minmax(0, 1fr) auto`, icon, title 13.5px/600, muted subtitle 12px and a relative time on the end side, truncated with an ellipsis; "More" row `padding: 10px 12px; radius 10`; empty `padding: 28px 12px`. Screen reader: container `role="search"`; input `role="combobox" aria-expanded aria-controls="ui-gs-panel"`, with `aria-activedescendant` naming the active result (`id="ui-gs-opt-<n>"`) while the panel is open, removed when it closes or the query empties; tabs `role="tablist" aria-label="Result types"` with `role="tab" aria-selected` (focus ring inset -2px); results `role="listbox" aria-label="Results"` with `role="option" aria-selected`, the "Open in" box included. v3: `gsMark`, per-kind state (loading, failed, count) drives tab text; search.js:19-33, 68-75, 136, 166, 190, 232-332, 333-337; ui.css:2656-2688; index.html:418-422.
- **SR-4 Search keyboard flow: /, arrows, Tab, Enter, Escape.** "/" anywhere outside a text field focuses the search (on a phone, opens the full-screen search); ignore it with Ctrl, Meta or Alt, in inputs, textareas, selects, contenteditable, and while a sheet, `[role="dialog"]` or `.modal` is visible. Keep focus in the input and move a virtual active index: Up and Down move the highlighted result across all kinds on the tab, wrapping with modulo, while the user keeps typing (and return focus to the input if it was on a panel button, except in the phone sheet); Tab and Shift+Tab switch the kind only while the query is non-empty (an empty field tabs normally), stepping over a kind that is not drawn (Suppressions without a kept list); on a kind tab, Left and Right step through tabs, mirrored in RTL (`(event.key === 'ArrowRight') !== rtl`); Enter opens the highlighted result; Escape closes the panel, empties the field and resets to All, with `stopPropagation` so a dialog underneath stays open. A new query starts again on the first result. A kind's tab starts on its first real result, not the "Open in" box. The active result gets `.ui-gs-item.is-active { background: --ui-panel; box-shadow: inset 3px 0 0 ink }` (RTL `inset -3px 0 0`), hover with a pointer (`@media (hover: hover)`) the same shade, `scrollIntoView({ block: 'nearest' })`, active index clamped when results shrink. On desktop `mousedown` `preventDefault` on panel buttons keeps focus in the field (not in the phone sheet). Footer "up down move · Tab type · Enter open · Esc close" as keycaps (11.5px, kbd mono 11px, `aria-hidden`). Screen reader: active row is `is-active` plus `aria-selected`, and the input's `aria-activedescendant` points at it while the panel is open, so a screen reader reads the result while the field keeps the focus; keyboard focus also gets an inset 2px ring. v3: `gsChoose`, `gsClose`, `gsSetTab`, `gsStepTab`; search.js:331-337, 382-417, 577-643; ui.css:2671-2677, 2689-2690.
- **SR-5 Local first; the server from two characters, debounced and cancelled.** Pages and settings answer synchronously on the first character. Messages, domains, mailboxes, suppressions and addresses wait for two characters (`GS_SERVER_FROM = 2`); with one the panel says so. Ask the server only after a 200ms pause: each keystroke clears the timer and aborts the previous `AbortController`, and results apply only if their controller is still current, so an older query never overwrites a newer one; each kind fills in as its answer arrives. The domain list (searched in the browser) and whether a suppression list is kept are fetched at most once a minute and reused. v3: `gsRun`; search.js:21-23, 140-145, 172-177, 219-256 `gsRun`.
- **SR-6 Opening a result goes to it and shows where it landed.** Choosing a page, setting, domain, mailbox, suppression or address clears and closes the search, goes there and shows exactly where it landed: wait for the element by polling every 100ms up to 8000ms, scroll it below the sticky bars (fields centered, details aligned to start with `scroll-margin-top: 80px`; if a sticky or fixed bar still covers it, scroll the nearest container back by the overlap + 12px), and ring it in blue for a moment (`ui-gs-flash 2s ease`: 3px focus-color ring at 45% held to 40% then fading, restarted by a forced reflow). A setting opens its tab, highlights its row, puts the cursor in the field (focus with `preventScroll`; a value kept in a hidden field, such as the Time Zone picker or Features, is found through its row and focuses the row's first enabled control) and re-checks every 150ms for 4000ms. A domain opens expanded; a mailbox fills the Mailbox Stats search and expands; a suppression opens Outbound > Suppressions searched for the value shown (a domain block by its domain) with the reason and state filters cleared, so every state is listed; an address opens Security > Events filtered to that IP with other filters cleared and page 1; a banned network, which has no events of its own, opens Security > Overview on the Banned list with the country and network filters cleared. The setting, domain, mailbox, suppression and address openers wait for `navigateTo` and stop when it resolves false (the user stays with unsaved changes). Pitfall: a mailbox or domain must open from its first line, also below page tabs that stay at the top of a phone screen, and the page is drawn again when the version check answers, so the setting's field has to be found again (#382). v3: `gsWaitFor`, `gsUncover`, `gsReveal(el)`, `gsOpenSetting`, `gsOpenSuppressions`, `gsOpenBannedNetwork`, `.ui-gs-target`, `.ui-gs-flash`; search.js:401-402, 419-559 `gsWaitFor`, `gsUncover`, `gsReveal`, `gsOpenSetting`; ui.css:2691-2694; router.js:243-246.
- **SR-7 A message opened from search comes over it.** Choosing a message opens it in its dialog over the search, which stays open behind (`keep: true` items). On desktop, when the message closes, focus returns to the search field with `preventScroll` so the user can arrow to the next result (a `MutationObserver` on `#message-modal`'s class waits for `hidden`); on phones the search does not put the focus back in its field, because that would raise the keyboard. On a phone the message appears above the full-screen search (search `z-index: 49` while a message is open, dialogs at 50); closing returns to the results, and Back closes the message first, then the search (#383). v3: search.js:132-134, 384-399; ui.css:2715-2716.
- **SR-8 Phone search covers the screen; a tab tap lets the keyboard go.** On a phone a search icon in the top bar (`aria-label="Search"`) opens the search over the whole screen: move the search element to `body` (and back to the top bar on close), `position: fixed; inset: 0; z-index: 90; padding-top: env(safe-area-inset-top)`; box 46px with 16px font (no iOS zoom), margins `10px 12px 6px`, a Cancel button; kind tabs as a horizontal scrolling strip (`overflow-x: auto; scrollbar-width: none`, active `inset 0 -2px 0 ink`); results fill the rest with `padding-bottom: calc(16px + env(safe-area-inset-bottom))`; the page behind cannot scroll (`html.ui-gs-locked` html and body `overflow: hidden`); key hints hidden. Tapping a kind tab dismisses the on-screen keyboard so the results get the room. Back closes it. Keyboard: input `enterkeyhint="search"`. v3: `.ui-gs.is-sheet`; search.js:342-356, 374-378, 389-391, 611-619; ui.css:2696-2716; index.html:408, 422, 424.
- **SR-9 List search: when it fires.** Fire a list search at the point that fits its cost: Enter (or the search button) for costly server queries (Messages, Security events, Suppressions, Live Logs); every keystroke (`oninput`) for in-memory filters (Mailbox Statistics, Devices, Domains, whitelist, rate-limit tables); a 300ms pause for paged server lists (Manage Reports, SR-10). Emptying the logs search clears it and its quick filters together (`oninput="if(!this.value)clearLogSearch()"`). The queue filter runs in memory but on Enter or Apply: a case-insensitive substring by sender or any recipient, with a separate queue ID field under Filters and empty text "No matching queue entries". The logs search covers message, program, URI, method, remote, data, service, priority, subject, senders, recipients, action, IP and user. The logs field and its two buttons shrink together before anything wraps: `.ui-logs-find { flex: 1 1 190px; min-width: 0; max-width: 320px }`, input `width: 0` with `flex: 1`. Screen reader: inputs carry `aria-label` ("Search logs", "Filter whitelist", "Search domains"); the whitelist filter is `type="search"`. v3: index.html:697-705, 825-826, 883, 889-890, 908-910, 1217, 1297, 1374-1377, 1645; app.js:3094-3124, 3196-3200; smtp-abuse.js:43-44, 128-141; logs-viewer.js:435, 590, 1034, 1187; domains.js:94-162; ui.css:2218-2221, 2285.
- **SR-10 A server-side list search: debounced, from page 1, kept for paging and deletes.** The Manage Reports search filters the server-paged list of all reports by domain or reporter after a 300ms pause, ignores a search equal to the last one, starts from page 1 and stays in the paging state for paging and after a delete; LIKE wildcards are matched literally. The total line switches between "Total: 312 reports" and "4 matching reports"; no match reads 'No reports match "x"'. Pitfall: #416 first put the search on the reports-by-domain table, then moved it to filter the paged list of all reports. v3: dmarc.js:1194, 1210, 1362.
- **SR-11 No filter field above a short list.** A short list (about ten log services) has no filter field above it; add a list filter only when the list is long enough to need one. Pitfall: the field existed and was removed in #315 because with only about ten services it only took space.
