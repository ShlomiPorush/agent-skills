# UI behavior rules (v3 style): Navigation, layout and routing

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `1d4f3e0` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Navigation, layout and routing

- **NL-1 App frame: the browser never scrolls, only regions do.** The browser window never scrolls (`html, body { height: 100%; overflow: hidden }`; shell and main `100vh/100dvh`); the sidebar and top bar never move, only the page area scrolls (`.ui-page` `overflow-y: auto; padding-bottom: 28px`). Pages with tabs or filters keep them fixed and scroll only their content region: mark it `.ui-scroll` (`overflow-y: auto; overscroll-behavior: contain; grid-auto-rows: max-content`) and give its page `overflow: hidden` (`.ui-page:has(> .ui-scroll)`); pages without one scroll as a whole. Messages scrolls its three columns separately, Logs fills the height with a fixed terminal, Settings scrolls nav and fields separately, a long Status attention list scrolls in its own box (`max-height: 34vh; overflow-y: auto`, none on phones and short screens). Sidebar `position: sticky; top: 0; height: 100vh` then `100%`, `overflow-y: auto`. At `(max-width: 760px), (max-height: 600px)` the page scrolls as one inside the frame (page `overflow-y: auto`, `.ui-scroll` `overflow: visible`) and the page tabs stick to the top (`.ui-page > .ui-tabs { position: sticky; top: 0; z-index: 6 }`); the phone terminal is `height: 65vh; min-height: 320px`. Screen reader: `nav aria-label="Main"`. Pitfall: the whole window used to scroll, so the page title, tabs and filters left the screen with the content (#284); on phones the split is not used so the header does not eat the screen, and #290 gave the Logs area one fixed height. v3: `.ui-scroll`; ui.css:1141, 2354-2404.
- **NL-2 Scroll regions must not squash their panels.** In a long scrolling page, cards and figure rows keep their height and rounded corners; nothing is squashed or cut, and the page can always be scrolled to its last panel. The scroll region grid uses `grid-auto-rows: max-content`, and panels that clip their corners use `overflow: clip` instead of `hidden` (`.ui-kpis { overflow: clip }`, `.ui-table-card { overflow: clip }`); never put `overflow: hidden` on a grid child that must keep its height. Pitfall: `overflow: hidden` made the summary numbers a scroll container whose minimum height in the page grid is zero, so a long list squashed them away; `clip` keeps the rounded corners without that (#318). On a DMARC domain the chart and the report list were cut off and the page could not be scrolled to the reports (#331); the fix was checked at two window heights. v3: ui.css:2368, 2521-2524, 2581.
- **NL-3 Every tab, section and level has its own address.** Pages have readable addresses (`/messages`, `/outbound`, `/rspamd`, `/security` for the internal route `netfilter`; the dashboard is `/`), and every tab, settings section and DMARC level has its own, so it can be reloaded, shared and reached with Back and Forward: `/security/lists`, `/security/settings`, `/security/events`, `/outbound/suppressions`, `/quarantine/rules`, `/status/blocklists`, `/status/jobs`, `/mailbox-stats/rate-limits`, `/settings/<section>` (any id matching `/^[a-z0-9_-]+$/`). The first tab is the page's plain address (`/security` is Overview, `/outbound` the Queue, `/quarantine` the messages, `/status` the server, `/mailbox-stats` the statistics); the first Settings section is `settingsFirstTab || 'features'`. DMARC & TLS has no tabs; its levels are `/dmarc/<domain>`, `/dmarc/<domain>/report/<date>`, `/dmarc/<domain>/source/<ip>` and `/dmarc/tls/<domain>/<date>` (a day of TLS reports), segments URI-decoded; the older `/dmarc/tls`, `/dmarc/tls/<domain>` and `/dmarc/<domain>/reports|sources|tls` open the domains or the domain, with the address corrected in place. A level opened inside a page that has no address of its own (a Rspamd map, a Rate Limits sender) is not in the address. Push or replace: a step the user takes adds a Back step, only when the path differs (`routerPush`): a tab switched on an open page (`routerSyncSubpage(route, name)`), a page opened with `navigateTo` (with a dialog or sheet open, it takes over the layer's history entry instead of stacking one more), a DMARC level opened (`dmarcPush`). Everything that only corrects the address replaces it without a Back step (`routerReplace`, or `routerSyncSubpage(route, name, true)`): the tab set while a page loads (loads that came from the address pass `updateUrl = false`), an unknown tab or settings section (the first one opens), a tab or view whose feature is off (the first one that is on opens), the legacy Security tabs, a moved page, an older DMARC level, and a switched-off page's own address. Back and Forward between tabs of an open page switch the tab without fetching the page again (`popstate` uses the stored `{ route, params }` or re-parses). An unknown page opens the dashboard, with the address left as typed. Old addresses keep working after a restructure through `canonicalRoute`, for a typed or bookmarked address, an internal link and a Back into a history entry an older version wrote: `/queue` opens `/outbound`, `/spam-filter` opens `/outbound/suppressions`, `/spam-filter/maps` and `/quarantine/maps` open `/rspamd`, `/settings/spam_filter` opens `/settings/outbound`, and `/security/protection|fail2ban|abuse` open the Settings tab (`fail2ban` and `abuse` also open their card). Every history entry carries its place (`idx`), so Back and Forward can be undone exactly; an entry an older version wrote has none, so the page shown is written back as a new entry before asking. The browser tab names the page and its open tab ("Mailbox Stats · Rate Limits · <app title>"). Back and Forward bring a page back to where each of its scrolling areas was scrolled, also a list that loads more as it scrolls; the user scrolling stops it. Helpers: `routerPush`, `routerReplace`, `routerRestoreScroll`, `canonicalRoute` in router.js, `queueDocumentTitle` in app.js. Pitfall: while a page loads, the address is corrected instead of adding a Back step (#329); section ids with underscores must be accepted, they once opened About (#340); a restructure keeps the old addresses working (#349 for the Security tabs, #385 for `/dmarc/tls` and `/dmarc/<domain>/sources`). Before the interaction fixes (history; where it differs from the text above, the text above is the rule): Pages have readable addresses (`/messages`, `/security`; the dashboard is `/`), and every tab, settings section and nested level has its own (`/security/lists`, `/settings/<section>`, `/dmarc/<domain>/...`), so it can be reloaded, shared and reached with Back and Forward; the first tab is the page's plain address. DMARC levels: `/dmarc/<domain>/<reports|sources|report|source>/<id>` and `/dmarc/tls[/<domain>[/<date>]]`, segments URI-decoded. Switching tabs on an open page adds a Back step (`pushState` only when the path differs); while a page is still loading its address is corrected in place, and loads that came from the address pass `updateUrl = false`. Back and Forward between tabs of an open page switch the tab without fetching the page again (`popstate` uses the stored `{ route, params }` or re-parses). An unknown tab opens the first one, an unknown page the dashboard, and old addresses keep working after a restructure (legacy `/security/protection|fail2ban|abuse` open the Settings tab and the matching card), all corrected without a Back step. Pitfall: #329 settled that while a page loads (replace) the address is corrected instead of adding a Back step; #340 found section ids with underscores were not accepted at first and opened About; #349 kept old Security addresses working and #385 added `/dmarc/tls` and `/dmarc/<domain>/sources`. v3: `SUBPAGES` table `{ tabs, current(), select(t), show(t), first }`, `navigateTo(route, { sub })`, `routerSyncSubpage(route, name, replace)` called on every tab switch; router.js:6-106, 134-232, 256-268, 613-620, 643-750; app.js:503-510, 1856-1863, 1899-1904, 4030-4039, 4845-4854; settings.js:11-13, 1846-1848, 1888-1899; dmarc.js:21, 82-88, 181-194; app.js:4043-4049; mailbox-stats.js:71-72.
- **NL-4 A page reopens on the tab it was left on; re-clicking resets it.** Going back to a page from the navigation lands on the tab the user last used there, with that tab's address: store the current tab per page in memory, and `navigateTo` without `sub` uses `SUBPAGES[route].current()` (Security, Outbound, Quarantine, Status, Mailbox Stats, Settings). The first tab may be dynamic (Settings: `settingsFirstTab || 'features'`). Clicking the current page in the navigation adds no duplicate history entry (`pushState` only when the path changes, `switchTab` always runs): a page without tabs loads its main view again (a DMARC domain or a Rspamd map goes back to its list), and a page with tabs shows its current tab again without loading the page (`SUBPAGES[route].show`). Pitfall: #334 made DMARC & TLS reopen its TLS tab and keep it on Refresh; #385 removed that page's tabs, so the rule now applies to the pages that still have tabs. v3: `SUBPAGES[route].current()`, `switchTab`; router.js:64, 265-295; app.js:1856-1862.
- **NL-5 Breadcrumbs instead of Back buttons; levels opened in place.** Each page starts with breadcrumbs instead of Back buttons: "Group > Page > Tab > opened item". Earlier levels are buttons that lead back (`.ui-crumb` underlined, `text-underline-offset: 3px`; in the top bar plain, underlined on hover with a pointer), the last is plain bold text (`.ui-crumb-current`); separator `>` (`›`), or `/` in the page's own crumb row on DMARC and Rspamd, `aria-hidden`. The tab crumb never includes its badge number (label taken from a clone with `.ui-tab-n, .ui-count, .ui-nav-count, .hidden` removed); the page crumb opens the page's first tab (or its main view). Levels opened inside a page or tab (a map on the Rspamd page, a DMARC domain, day or sender) join the same trail for as long as that page or tab is open ("Protection > Rspamd > <map>"); a sender crumb first shows the clicked IP and upgrades to the network owner's name when details arrive (`name = group.name || asn_org || sourceIp`); the way back from a Rspamd map asks before dropping unsaved changes (`rspamdLeaveMap`). The last crumb follows tab changes by click, Back or flyout (`MutationObserver` on `.ui-content` for `aria-selected`, `aria-current`, `class`, batched per frame). On wide screens the trail joins the top bar; on a phone the page's own crumb row stays as the way back and hides at the root. Some levels open in place inside their card with a `"<- All senders"` back button and survive a reload. Screen reader: `<nav aria-label="You are here">` (top) or `aria-label="Breadcrumb"`; current crumb `aria-current="page"`. Pitfall: the breadcrumb is pulled up 6px to sit close to the tabs; on the Rspamd map editor it lives inside the scroll region, so the pull-up put its top above the region's edge and the region cut it off (#340); inside a scroll region the crumb's negative top margin is dropped. v3: `updateTopbarCrumbs`, `setPageCrumbs`, `topbarSubLabel`, `topbarOpenPage`, `watchTopbarCrumbs`; app.js:716-719, 747-817; dmarc.js:97-116, 826, 837; spam_filter.js:52, 120, 146, 155, 255-257; rate-limits.js:301, 390, 400, 449; ui.css:1811-1818, 2653-2657; index.html:1179.
- **NL-6 One top bar on wide screens, with the page title and actions moved up.** On wide screens one 60px bar runs across the top (rows `60px minmax(0, 1fr)`): logo, app name and menu toggle (brand area `min-width: 240px`), then the current page title with its help button (`max-width: 40%`, 20px, ellipsis), then the search, pushed to the end side (`margin-inline-start: auto`), and after it the page's own action buttons (`flex: none`, never wrap). The page itself starts with breadcrumbs and its description; local crumbs are hidden; `ui-has-topbar` is set on html. Title and actions are the page's own elements, moved (not copied) and put back on leaving, so every id, button and listener keeps working. Skipped for `messages` (keeps its own layout) and `(max-width: 760px)`; the bar is re-placed live when the viewport crosses 760px. Pitfall: the name sat at the top of the sidebar, so folding the menu cut it off (#375); moving the real elements up instead of copies keeps every id, button and listener as it was. Example: the DMARC sync note is too tall for the bar, so it stays with the description. v3: `topbarMove`, `topbarRestore`, `placeTopbar` with a media-query listener; app.js:642, 671-725; ui.css:2633-2660, 2702-2703; index.html:414-429.
- **NL-7 Sidebar folds into an icon rail, remembered, without a flash.** A toggle by the brand folds the desktop sidebar (`html.ui-nav-collapsed` at 1101px and up) from 240px into a 72px icon rail with an animated width (`transition: grid-template-columns .18s ease`); the toggle moves under the logo and its icon flips. Items become `48px x 42px`; labels, group labels, the server card, the footer's version lines and the tab arrow (`.has-sub::after`) are hidden, and the footer's tool buttons stack in a column. Counters become colored dots at the icon corner (`position: absolute; top: 7px; inset-inline-end: 8px; 8px x 8px; font-size: 0`, red with `.is-fail`); hovering an icon still opens its page's tabs, and the flyout closes when toggling. On reload the folded state is applied before the page draws, so it never flashes open: `localStorage.navCollapsed` `'1'`/`'0'` is read in an inline script in `<head>` inside try/catch (private mode safe). Between 761 and 1100px the sidebar is always a rail without the toggle. Nav items keep a `title`, also updated when a tab is renamed, so the rail stays understandable. Keyboard: toggle `aria-label`/`title` "Collapse menu" / "Expand menu" with `aria-expanded`. Pitfall: the rail and its memory came in #323 with the app name and toggle at the top of the sidebar, so folding the menu cut the name off; #375 moved the app name and toggle into the top bar. v3: `toggleNavCollapsed()`, `syncNavToggle()`, `setNavTabLabel`; ui.css:1168-1171, 1192-1207, 2603-2631; index.html:17-18, 440; app.js:381-386, 6251-6272.
- **NL-8 Sidebar flyout of a page tabs, with a hover bridge.** Hovering or focusing a sidebar item for a page with two or more tabs (`.ui-nav-item.has-sub`, with a small arrow) shows a small menu beside it with those tabs, their counters and the current one marked (bold with a 6px dot); clicking one opens the page on that tab. Items come from the page's own tab buttons, so tabs hidden by a switched-off feature are not offered. Flyout `.ui-fly` `position: fixed; z-index: 60; min-width: 210px`; closed `opacity: 0; visibility: hidden; transform: translateX(-4px)`, open `opacity: 1; visible; none`, `transition: opacity .12s, transform .12s, visibility .12s`; position beside the sidebar (`left = rect.right + 8`, or `rect.left - width - 8` when the page reads right to left; it slides in by `translateX(4px)` under RTL), `top = rect.top - 6`, clamped 8px inside the viewport. A hover bridge (`::before` 12px wide at `inset-inline-start: -12px`) keeps it open while the mouse crosses the gap; it closes 150ms after leave or blur, and on resize. Never on `(hover: none)`: touch screens keep the in-page tabs. Keyboard: item `aria-haspopup="menu"`, flyout `role="menu"`, items `role="menuitem"`; ArrowRight opens and focuses the first item, ArrowDown/ArrowUp move with wrap, Escape or the arrow back toward the sidebar (ArrowLeft, ArrowRight under RTL) close and return focus; focus leaving closes it.
