# UI behavior rules (v3 style): Feedback, loading and empty states

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `0210d15` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Feedback, loading and empty states

- **FB-1 Locked, not hidden.** When a feature needs something missing (a Read-Write API key, a password, a licence, IMAP, a setting), the control never just disappears. Either keep it visible but `disabled` with the reason in `title` ("Fetching reports needs IMAP set up in Settings"), or put a dashed locked box in its place: lock icon, bold title ("Ban, Allow and Unban are locked"), the reason naming the missing key or variable, and an Open Settings button (on phones under the text); box grid `20px minmax(0, 1fr) auto`, `border: 1px dashed muted 55%`, full-page variant `min-height: 50vh`. Shared reason text: "needs a Read-Write API key (MAILCOW_API_KEY_RW). Configure it in Settings -> Mailcow -> Connection.". Repeat the note inside a dialog when the list note is hidden behind it; tabs and sub-menus stay present; rules say what they can see ("Only SMTP logins are checked. IMAP logins need Live Logs to be on."). When the key status arrives after the page drew, draw actions and locks again. Locked abuse controls keep the activity readable, hide buttons and disable the textarea, and distinguish a missing key (Open Settings) from protection being off (points to the card's switch); read-only maps get `readonly aria-readonly="true"`; a disabled Reset button still stops the row click. The About page shows one card per dependency saying whether it is set up and working, with a Settings button; the Read-Write key and Rspamd cards give the last credential check of the saved key ("Accepted", or what was wrong; "It has not been checked yet." before the first). Keyboard: native `disabled` plus `title`; lock icon `aria-hidden`. Pitfall: parts of the app disappeared when a key or setting was missing with nothing saying why (#337), and #262 replaced a yellow banner, an overlay and silently missing buttons with this component (#256). A switched-off job used to show "idle" and silently lose its Run button (#264), and the map editor now opens read-only instead of offering a Save that fails (#293). The one reversal: #433 hides Upload Report again when manual upload is off, following Settings without a reload. v3: `uiLocked(title, trustedHtml, action = 'settings' | customHtml | '')`, `.ui-locked`, `.ui-disabled-page`, `UI_RW_KEY_TEXT`; utils.js:179-192; ui.css:245-262, 972-975, 1209-1213, 2034-2036; app.js:447-458, 1379-1380, 2598, 2900, 3217-3242; security.js:634-635, 836, 1155-1210, 1254-1293; about.js:75-81.
- **FB-2 Toasts: one at a time, four seconds, announced.** Every action ends in a toast at the bottom end corner (`position: fixed; bottom: 18px; inset-inline-end: 18px; z-index: 100000; max-width: min(420px, calc(100vw - 36px))`) with a 4px colored start border and an icon by type (`'success' | 'error' | 'warning' | 'info'`; unknown types fall back to info). A new toast replaces the current one instead of stacking. It stays `4000ms`, then fades (`opacity .3s`) and is removed after `300ms`; it waits while the pointer or the focus is on it, then gives the rest of its time (at least 1.5 seconds), and can be closed earlier with X. Long text wraps anywhere. On phones it sits above the tab bar at `bottom: 76px`. Screen reader: errors `role="alert"`, others `role="status"`; icon `aria-hidden`; close `aria-label="Close"`. v3: `showToast(message, type)`; utils.js:641-701; ui.css:2089-2101, 2116.
- **FB-3 Errors say what failed and what to do.** Failures say what failed and what to do next: "Could not load this: <reason>. Try again in a moment.", "Failed to load <thing>: <reason>", where the reason is the server's own message (else "HTTP <status>"), never "Internal server error"; a validation error (FastAPI 422) reads each field as "field: problem" (`uiApiErrorText`). When mailcow does not answer, pages say "mailcow did not answer. Try again in a moment."; when Fail2ban does not answer, Security says so instead of showing nothing banned (ban buttons hidden, "No answer" on the card). Lists that can be retried show a Retry button; the count next to a failed list is cleared; settings show "Failed to load settings" in place of the spinner. CSV export checks first (HEAD with the current filters, then a temporary `<a download>`) and explains: "Download started.", "No data to export. Try different filters." (404), "Could not export CSV. Check the filters and try again." (422), "Could not export CSV. Refresh the page and try again." (not CSV), "Could not export CSV. Please try again.". Screen reader: error toasts are alerts. Pitfall: a failure reached the route as an unknown exception and the page showed "Internal server error" (#392, #395, issue #384); carry the server reason through. An unreachable service looked like nothing banned until #348 made the Overview say mailcow did not answer. v3: `responseError`, `uiApiErrorText`; export.js:5-39; app.js:112-121, 2426-2428, 2541-2543, 2871, 4043-4045, 4297, 4346; security.js:636-642, 785-787, 1268; settings.js:1474-1482; utils.js:846-861.
- **FB-4 Toasts name the object and the result.** Success and error toasts say what and which, in words for the person, built from the object name and its new state: "1.2.3.4 removed from the denylist", "Could not remove 1.2.3.4: <reason>", "user@x can send again", "user@x is limited to 100 per hour", "Map saved (40 entries)", "postfix is ignored. It no longer counts or alerts." / "postfix counts again.". Error toasts use the server detail when present. Screen reader: the shared toast roles. v3: app.js:4209-4221, 4704-4717; security.js:872-876, 1065-1066; protection.js:248; rate-limits.js:596, 1114-1116; spam_filter.js:356, 947.
- **FB-5 Empty states explain why and what comes next.** An empty list says what would be here and when or how it appears, with a bold first line and a plain second line: "No reports yet. They arrive from the report mailbox, or upload one with Upload Report."; "No rules configured. Click "Add Rule" to create one."; an empty chart suggests "Widen the window to look further back."; reading panes say "Select a message..."; the dashboard says "Nothing needs attention right now.". Padding `36px 16px`, reading pane `60px 40px`. v3: `.ui-empty`; ui.css:563, 1204-1207, 1252, 1361, 2543; app.js:1242, 1350-1352, 2346, 2592, 2893, 3314, 3707, 4292, 4609-4614; security.js:592-595, 639-642.
- **FB-6 Loading states name what is loading.** Wherever data is coming on the first load of a view, show a centered spinner with a specific line saying what is loading ("Loading DMARC reports...", "Loading the domain...", "Loading details...") (see TB-5 for reloads). Markup `<div class="ui-loading" role="status"><div class="loading"></div><p>Loading...</p></div>`; spinner 24px with a 2px border (base 40px, 3px), `spin 1s linear infinite`. Screen reader: the loading block is a status region (`role="status"`), so the line is announced. v3: ui.css:278-280; index.html:56-73; app.js:2398, 2515, 2855, 3106, 4006; dmarc.js:70.
- **FB-7 Busy buttons say what is happening, then the result.** Long actions set `disabled` on their button and change its words ("Fetching...", "Unbanning...", "Allowing...", "Banning...", "Running..." with a spinning icon, "Checking...", "Signing in..." with the small `.ui-spin` ring), then restore the label in `finally`, or show a check and "Done" (reverts after `3000ms`) or "Error" (after `2000ms`) before returning by themselves. Ring `animation: spin 1s linear infinite; margin-inline-end: 6px`. Result states: done or on green, failed red (`.ui-btn-done`, `.ui-btn-failed`, `.ui-btn-on`: text color plus a 40% border). Keyboard: native `disabled`. v3: `.ui-spin`; ui.css:1015-1018, 1801-1802, 2006; app.js:1452-1455, 1493-1496, 1534-1537, 4443-4453, 4923-4928; about.js:198-235; login.html:117-123.
- **FB-8 No data is not a failure.** Distinguish "zero of something" from "nothing to measure" in every rate: a rate with nothing behind it (no messages, no TLS sessions) shows a muted "-" instead of a red 0%. Without mail in the period, SPF and DKIM say "No mail in the last 30 days" with a "No data" tag. The DMARC home "Passed DMARC" figure is the volume-weighted average, 1 decimal, in its tone, or a muted "-" with no messages. A domain with reports that is not on this server gets a small superscript "Not on server" (tooltip "This domain is not on this server."; on phones it reads beside the domain); nothing is marked while the server's domains are unknown. Status says "Everything is running. Nothing needs you right now." only once containers and jobs have both loaded; until then a spinner. Pitfall: after 30 days without reports a removed domain's row showed 0% DMARC pass in failure colour (#415, issue #412). The note then went through three wording passes (superscript next to the domain name, a shorter tooltip, mailcow dropped from it), and #434 put "Not on server" beside the domain on phones. v3: app.js:4151-4156; dmarc.js:34, 42, 256-264, 481-487, 703.
- **FB-9 Say since when when the data is shorter than the period.** Compute the real start of the data: when the logs do not go back as far as the chosen period, show a muted "since Oct 3" (the day in the app time zone) beside the period picker (tooltip "The oldest log line kept"), and every row says "since Oct 3" instead of "in the last 30 days". Security periods `[1, 7, 30, 90]` days, the picker hidden on History. Summary cards name their period under the number: "Today", "Last 7 days", "Last 30 days", "Last 90 days", "<start> - <end>", "Custom Range". Pitfall: "Today" used to label what is really the last 24 hours, and the text says that now (#351); #386 labels the period as it really is, because the logs may start after the chosen one. The Overview count stays on the last day while a filter lists a longer period. v3: security.js:38, 654-657, 681-701; mailbox-stats.js:193.
- **FB-10 Needs attention: only what needs a decision, each with its action.** The Dashboard and Status open with only what needs a decision, each row with a `4px` colored bar, text and its one action: mailcow not reachable (Open settings), a host on a blocklist (Check listing), stopped containers (Ignore, Open status), failed jobs (Run now), Fail2ban entries an earlier version wrote as whole /32 networks (Open lists; "A Fail2ban entry blocks the whole <network> network", "N Fail2ban entries cover whole /32 networks"), DMARC issues (Open DMARC), updates (Read changes), unacknowledged security alerts (Show activity, Dismiss). The count sits beside the heading; empty, it says so. A row whose action opens a popup (`.ui-alert-go`: updates and security alerts) opens it from anywhere on the row except its buttons or a text selection, with hover `ink 3%` only with a pointer (`@media (hover: hover)`); on phones the actions go under the text (grid `4px minmax(0, 1fr)`). Blocklist wording: "N of your addresses are on a blocklist" for several hosts, "<host> is on a blocklist" for one, "Listed on X of Y lists. Outbound mail to some providers may bounce.". Security alerts: `limit=20`, `acknowledged=false`, CRITICAL red or WARNING amber; "Dismiss all" only when there are alerts, no confirmation, toast "All security alerts dismissed". Pitfall: Status was one long scroll of containers, blocklists, 25 jobs and data tables until #281 led it with attention rows. On phones the button took half the row until #424 moved actions under the text. v3: `.ui-alert-go`; app.js:1927-2065, 2184-2201, 4126-4164; ui.css:310-317, 1241-1251, 2630-2634.
- **FB-11 Ignore without hiding.** A container stopped on purpose or an irrelevant blocklist can be ignored from Status: it stays visible, greyed with an Ignored mark and a grey dot, and no longer counts in totals, alerts, counters or the blocklist email; "Stop ignoring" is always beside it. Container tooltip "Ignored: shown here but never counted or alerted". Lists ignored for every address are gathered in one "Ignored lists" panel with a count (note "Checked and shown, never counted or alerted, for every address"), so the way back is always visible. No confirmation; the toast explains. A down container tints `fail 10%`; the ignore button turns ink on hover, only with a pointer (`@media (hover: hover)`). Blocklist panels list listed lists first with Look up and Ignore list, the others folded into "N other lists" / "All N lists". Screen reader: lookup icon `aria-label="Look up on <list>"`; tooltips "Stop counting and alerting on <name>", "Keep checking this list but never count or alert on it". v3: `.ui-ctr.is-down`, `.is-ignored`, `.ui-bl-ign`; app.js:4250-4286, 4603-4698; ui.css:1402-1435.
- **FB-12 Click to copy wherever a value is shown.** IDs, addresses, IPs, usernames, queue and message IDs, DNS records and names copy on a click wherever they appear (tooltip "Click to copy"). With a pointer (`@media (hover: hover)`), hover tints the value `rgba(59,130,246,.08)` (dark `.15`) and shows a faint copy icon (`opacity: 0` -> `.5`, `.15s ease`); after copying a toast says "Copied: value" and the icon turns into a check (`opacity: 1`) for `1500ms`. Clicking a copyable value inside a clickable row copies without opening the row (`stopPropagation` and `preventDefault`). Empty values and "-" render as plain text. In compact lines the icon shows only while the pointer is on the value; a long DNS record wraps (`display: inline; overflow-wrap: anywhere`) and keeps its icon at the end of the last line. A refused clipboard shows "Failed to copy"; without a clipboard (plain HTTP) the error toast says "Copying needs HTTPS. Select the text and copy it yourself.". Screen reader: copyable text wrapped in `<bdi>`. Pitfall: compact cells hid the copy icon so it would not open gaps in the text, and the value no longer said it copies; #322 shows it while the pointer is on the value. In Quarantine rows values became plain text so the row opens and the dialog still copies them (#340). v3: `copyableText(text, extraClasses)`, `copyToClipboard(text, event)`, class `ui-copy-wrap`, `.copied`; utils.js:602-639; index.html:354-386; ui.css:1343-1347, 2325-2326, 2867-2868.
- **FB-13 A tick for a protection that acts, an eye for one that only watches.** Above the Security list every protection is a pill with a mark and a short note ("5 attempts, 1h", "bans", "watching", "alerts", "needs MaxMind GeoIP", "needs a Read-Write key"): a green tick when it acts (bans), an amber eye when it only watches, an outline when unknown, grey when off; tick and eye both count as on. Outgoing spam shows off with "needs a Read-Write key" while the key is missing, because its check does not run then. Mark is an 18px circle; pill hover `inset 0 0 0 1px line`, only with a pointer (`@media (hover: hover)`). Clicking a pill opens that protection's settings card. Screen reader: mark `aria-label` On / Watching only / Unknown / Off; button `title` "Fail2ban: On, 5 attempts, 1h". Pitfall: a protection that was on showed the same green tick whether it banned or only watched; #373 separated "on" from "acts". v3: security.js:204-258; ui.css:675-688.
- **FB-14 Tones follow meaning.** Use one tone map per domain concept for tags, dots and edges: delivered and sent green, deferred amber, bounced and rejected red, spam its own color, anything else neutral; direction tags keep their own colors (inbound indigo, outbound blue, internal teal) as dots in facets and tags in lists. Each message row has a `border-inline-start: 3px` edge for its final status (ok at 55%; a still-incomplete one the warning edge). Quarantine "add header" reads as a warning, not a failure. Pass rates green from 95%, amber from 80%, red below; failure rates amber from 5%, red from 10%; scores red from 15, amber from 6; KPIs turn red or amber only above zero, a zero stays quiet. Queue states: hold none, deferred warn, active ok, incoming info, bounce fail, corrupt fail. Correlation tag "Linked" / "Pending" (tooltip "Waiting for Postfix logs"). The status word carries the meaning; no checkmark or cross symbol. Screen reader: the number or word is always shown, so color is not the only signal. Pitfall: reject is the strong verdict, add header and softer ones read as a warning (#279). Direction colors were lost in the redesign and restored in #285, then applied to Mailbox Statistics where the link cell used to override them (#322); #268 dropped the old badge's symbol because the tone carries it. v3: `uiTag(text, tone)`, `uiStatusTag`, `uiDirectionTag`, `uiActionTag`, `uiCorrelationTag`, `UI_STATUS_TONE`, `.ui-msg-ok|warn|fail|spam`; utils.js:132-165; app.js:1230-1235, 2624-2626, 3143-3181; dmarc.js:26; mailbox-stats.js:334, 467, 528; ui.css:343-350.
- **FB-15 Authentication-off warning: Dashboard only, dismissible per browser.** With no sign-in configured, the Dashboard only warns "Authentication is off. Anyone who can open this page can see all mail logs and change settings." with Set up sign-in and Dismiss. Show it only on an explicit `auth_enabled === false` from the server; the demo hides it. Dismiss hides it for good in this browser (`localStorage.authOffBannerDismissed = '1'`), because a reverse proxy may already sign users in. On phones the action drops under the text and the X stays at the top end: text `flex-basis: calc(100% - 78px)`, X `order: 1; margin-block: -6px 0; margin-inline: 0 -8px`, button `order: 2; margin-inline-start: 32px`. Screen reader: `role="status"`; X `aria-label="Dismiss"`. Pitfall: #410 first warned on every page, then moved the banner to the Dashboard only and made it dismissible, then dropped its reverse proxy hint; #424 hid it in the demo. v3: `dismissAuthOffBanner()`; index.html:579-589; ui.css:231-243; app.js:519-531, 611-614.
