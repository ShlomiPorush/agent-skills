# UI behavior rules (v3 style): Forms, settings and secrets

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `1d4f3e0` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Forms, settings and secrets

- **FS-1 Whole toggle row is clickable.** For on/off settings, clicking anywhere on the row (title, description or switch) flips it and the save bar counts the change; the switch sits at the end edge and the row is marked on or off at once. Make the row a `<label for=...>` wrapping text and checkbox (`.ui-set-bool-main`, `.ui-feature`) with `flex-direction: row-reverse` and `cursor: pointer` (env-locked `not-allowed`); rewrite the description `<p>` to a `<span>` so the label holds only phrasing content; the features row gets `is-on`/`is-off` via `el.closest('label')`. The same idea makes a whole search box focus its field (`<label class="ui-search">` wrapping its input, `:focus-within { border-color: accent }`) and a checkbox's text clickable (`.ui-check-label` with `accent-color`). Keyboard: a native checkbox inside the label, so the whole text is its accessible name; Space toggles. Pitfall: only the title of a Settings switch row was its label and a click on the description did nothing; #338 made the row the label, as on the Features list, with the row looking exactly as before (screenshots compared pixel by pixel). Deliberate exception (#352): on Security cards the switch does not open the card, so toggling a protection never also expands it (FS-13). v3: settings.js:1312-1320; app.js:399-424; ui.css:582-585, 1012, 1113-1115, 1708, 2086-2096, 2109-2120, 2162-2164; index.html:699-700, 885-886, 1254-1255.
- **FS-2 Switch built from a real checkbox.** Checkboxes in settings and protection cards render as iOS-style switches that slide and turn green but remain real checkboxes for keyboard, forms and screen readers: `appearance: none`; track `38px x 22px` radius 11 (cards `36px x 20px`), knob 16px white with `box-shadow: 0 1px 2px rgb(0 0 0 / .2)` (cards `.25`), travel `translateX(16px)` (RTL `-16px`), `transition: background .15s`, `transform .15s`, checked `--ui-ok`, locked `opacity: .6`. A focus ring appears only for keyboard focus, on the visible track: `:focus-visible` 2px ring offset 2. On cards the input is visually hidden (`position: absolute; opacity: 0; 1px x 1px`) and the ring comes from `input:focus-visible + .ui-sec-switch-track`; `:has(input:disabled)` gives `not-allowed; opacity: .55`; Fail2ban reserves `36px` so names line up. Screen reader: card switches are `role="switch"` with the protection name as `aria-label`, track `aria-hidden`. v3: `.ui-check` on a checkbox, `.ui-sec-switch` label around a hidden input plus `.ui-sec-switch-track`; ui.css:843-866, 2096-2105; security.js:1301-1303.
- **FS-3 Stored secret: Stored, with Replace and Remove; the field appears only on Replace.** A saved password or key is never shown as a masked field: the server returns it as `********`, kept in a hidden input, and the row says "Stored" with two small buttons, Replace and Remove. Replace inserts a `type="password"` input with the same name and id, placeholder "New value", `autocomplete="new-password"`, that takes the focus at once and dispatches a bubbling `input` event so it counts as an unsaved change. Remove does not delete: it toggles the hidden value between `''` and `********`, the state turns red and bold "Removed when you save" (`is-removing`: `color: fail; font-weight: 600`) and the button becomes "Keep". An env-provided secret reads "Stored in the environment" with no buttons; an unset one is a password field with placeholder "Not set". The payload skips a sensitive key still `********`, so saving never resends an unchanged secret. Clear on a sensitive text field empties it and switches it to visible text; secrets never get Changed or Reset. Sensitive keys: mailcow_api_key, mailcow_api_key_rw, auth_password, oauth2_client_secret, smtp_password, dmarc_imap_password, session_secret_key, maxmind_license_key, rspamd_password. Keyboard: focus moves into the new field. Pitfall: #283 replaced the masked field with Stored, Replace and Remove, showing the field only when the user starts the change, while the save still never sends the mask; #279 fixed the side effects: Settings had marked stored secrets as changed, had not treated the Rspamd password as a secret, and had shown "Reset to default ()". v3: `settingsReplaceSecret`, `settingsRemoveSecret`, `.ui-set-secret`, `.is-removing`; settings.js:37-39, 1073-1102, 1258-1292, 1365-1366, 1919-1921, 2021-2022; ui.css:2081-2084.
- **FS-4 Reveal a field only when the choice needs it.** A field that matters only for one choice appears when that choice is made: toggle `hidden` on the dependent field on `change`, which also removes it from the accessibility tree. Add Suppression (Outbound > Suppressions) starts with "Permanent block" ticked; unticking reveals "Expires after (days)" (default 7, min 1, max 365). Edit Suppression shows an "Expiry date & time" field (a wall time in the app's time zone) that opens with the block's current expiry, or empty for a permanent block; unticking "Permanent block" with the field empty fills a week from now; with +7, +14, +30 and +90 day chips that add to the field's value, or to now when empty. Message: "Please set an expiry date". Choosing Domain changes the label and placeholder and adds a hint. An alert destination shows only the fields its service needs; switching service clears the service values but keeps name, enabled state and alert choices. Required fields carry a red asterisk, others "(optional)". In Settings, dependencies are expressed as disabled states and notes instead: a group that does nothing while a switch is off (`needs:` on a group; `SETTINGS_FIELD_NEEDS`, empty now, is the hook for a single field) stays in place but greyed out and unclickable until every switch it names is on (`settingsShowNeeds`: `inert` plus `.is-off`, `opacity: .5`), and a delivery-failure option that blocks shows "Needs Sync with Rspamd." while that switch is off; the hook `.ui-set-group/.ui-set-field/.ui-set-bool[hidden] { display: none }` exists but no settings code sets it. Keyboard: focus goes to the address field on open. v3: spam_filter.js:811-895, 968-1027; notifications.js:108-122, 188-208; ui.css:2049; settings.js:376-393, 1044-1051; ui.css:826.
- **FS-5 Changing a server asks for its password again.** If a server field tied to a stored password really changes (SMTP host, IMAP host, mailcow URL) and the save does not bring a new password, refuse the save with a short message asking to re-enter it. On submit compare the normalised server value with the loaded one: empty equals unset, `587` equals `"587"`, trailing slash ignored, ENV-locked fields skipped, so an ordinary full-form save still works. Pitfall: before #401 the app kept the saved password and sent it to the new server.
- **FS-6 Changed and Set by ENV marks; Reset names the default.** A setting that differs from its default gets a small blue "Changed" pill (tooltip "Differs from the default"; pill 11px weight 700, radius 6px, `info 14%` background) and a blue "Reset to default (60)" text button (`.is-reset`, info color) that names the default ("Reset to default: true", the option name for a segmented control, "(empty)" for an empty default); numbers are compared numerically, and an empty time zone counts as its default, UTC. A choice that stands for several settings (the Outbound delivery-failure choices) is marked Changed while any of them differs from its default; its Reset reads just "Reset to default" and puts back every one of them not set by ENV, and its lock pill names the variables ("Set by ENV: <VARIABLES>"). Credentials, hosts and addresses get a plain "Clear" instead, which turns red on hover where there is a pointer (`.ui-set-clear:hover` fail inside `@media (hover: hover)`) and is not shown for empty, default or env-locked fields. Clicking Clear or Reset sets the field, removes the marks and the button disappears; both must trigger the dirty count themselves (SV-2). A value set by an environment variable shows a lock pill "Set by ENV" (tooltip "Set by an environment variable, change it there"; lock icon 12px) and a disabled control with placeholder "Set by ENV" (`opacity: .7`); lists name the variable ("Set by ENV (DISABLED_FEATURES), change it there"). Never show Changed for secrets, user-specific keys or env-locked keys, and never Clear or Reset on an env-locked value. Screen reader: the lock SVG is `aria-hidden`. Pitfall: colour classes were replaced in #277 by one is-changed mark for values that differ from their default, and #283 made Set by ENV and Changed marks next to the label. v3: `.ui-set-pill`, `.is-changed`, `.ui-set-clear`, `.is-reset`, `.ui-set-field.is-locked`; settings.js:1154-1156, 1166-1168, 1213, 1234-1283, 1300-1304, 1366, 1908-1937, 444-459, 634-651; ui.css:2068-2079.
- **FS-7 Read-only until settings are migrated.** Before the first "Migrate Settings from ENV", all settings are visible but disabled and faded: wrap the form in a `<fieldset disabled>` with `display: contents` (no layout change), groups `opacity: .6`, with the primary migrate button and the note "Click once to copy your current configuration into the database. After that you can edit the fields below and save." Section navigation still works. Migrating asks for confirmation ("Import from ENV": "Import current configuration from ENV into DB? This will overwrite existing DB-stored values.", Import), disables itself while running, then reloads Settings; a failed migrate shows an error toast "Import failed: <server detail>". When editing is switched off entirely, the page shows a lock notice "Editing settings is off" naming the variable to set (`SETTINGS_EDIT_VIA_UI_ENABLED=true` in `.env`, then `docker compose up -d`, since a restart does not read `.env` again) and a read-only facts grid. Cards elsewhere that depend on settings show the same locks. Keyboard: a disabled fieldset disables every control inside. Pitfall: #337 let the save bar show before migration, and people typed their changes, found no way to save them and lost them when leaving the page; #355/#358 disabled the fields instead, and #372 kept the top row with the migrate button only before migration. Example: the Outgoing spam card shows lock notices with Open Settings. v3: settings.js:1602-1622, 1795-1805, 1812-1834, 2218-2236; security.js:1196-1210; ui.css:822-827.
- **FS-8 Settings page anatomy.** Settings sections are listed in a sidebar under small uppercase group headings (General, mailcow, Alerts, Security, Data; 11.5px, weight 700, `.04em`, uppercase), the open one highlighted like main navigation. Each section opens with a large title (22px weight 800, `-.02em`) and a one-paragraph explanation (`max-width: 75ch`, line-height 1.5), then small panels per group (Connection, Rspamd, Advanced) instead of a wall of fields; some start with a Status panel (key checks, Test SMTP, Test IMAP, MaxMind health). Each row has label and explanation (12.5px muted) at the start and the control at the end: grid `minmax(0, 1fr) minmax(0, 1.1fr)`, gap `4px 28px`, padding 14px, 1px rule between rows, a three-way `.ui-seg` at `justify-self: end`; on phones everything stacks. Control type follows the value: a switch for on or off, a segmented control for a few short choices (FS-14), a picker with a search for a long list (Time Zone, "Not set (UTC)" when empty), and where one decision sets several settings a list of radio cards under "What should happen?" whose options say in plain words what happens ("Block new mail to the address and delete its queued mail") and what they still need (the Outbound delivery-failure groups, each opening with a one-line intro); every setting has a plain sentence, many ending in "Default: X". Screen reader: `<nav aria-label="Settings categories">`, open item `aria-current="true"`; the radio cards are a `role="radiogroup"` labelled by "What should happen?". v3: `SETTINGS_TAB_GROUPS`, `SETTINGS_FIELD_DESCRIPTIONS`, `SETTINGS_FIELD_OPTIONS`; settings.js:193-842, 1065-1071, 1228-1231, 1348-1365, 1681-1787, 395-459, 1322-1346; ui.css:2033-2067, 2193-2196.
- **FS-9 Nothing silently hidden in settings.** No setting silently disappears: a visible section not assigned to a group is appended to the last group, a group with no visible sections is dropped, any editable key the UI does not know is rendered in an extra "Other" section rather than dropped, and a section shows only if one of its keys is editable (MaxMind always, for its status block). The one deliberate exception is a section that belongs to a feature that is off (Domains, IP Blacklist, DMARC & TLS and its IMAP, Outbound with Suppressions, Quarantine, Devices): it goes with its feature, as the Features section says; Logs stays, because other pages read its logs. v3: `isTabVisible`, `settingsTabOff`; settings.js:1061-1064, 1628-1659, 1703-1704, 1122-1137.
- **FS-10 Settings nav and fields scroll separately; sticky picker on narrow screens.** The section list stays in view beside the fields, which scroll on their own: grid `220px minmax(0, 1fr)`, gap 28; nav `position: sticky; top: 16px; max-height: calc(100vh - 32px)`; in the app frame nav and content are `height: 100%; overflow-y: auto`, content `overscroll-behavior: contain; padding-bottom: 96px` (room for the save bar). On a wide screen a newly opened section starts at its top: the fields column scrolls back to 0 if it was scrolled. At 1023px and below the sidebar becomes one sticky dropdown (`position: sticky; top: 0; z-index: 20; padding: 8px 0`) with group headings as optgroups; choosing a section smoothly scrolls the page's own scroll area, not the app frame, so the section starts just under the picker (offset = picker height + 8px, `behavior: 'smooth'`), only if it is above. On phones and short screens the page scrolls as one. Screen reader: the picker has an sr-only label "Settings category". Pitfall: `scrollIntoView` can pan the window on phones, so #311 scrolls only the settings area (`scrollTo` on the region); a section id with an underscore opened About when entered or reloaded (#340); the section list's grid grew to the search field's natural width, 29px wider than its column, and a leftover negative margin cut the first intro line (#372). v3: settings.js:1662-1679, 1863-1906; ui.css:2031-2040, 2188-2192, 2382-2386, 2402-2403.
- **FS-11 A closed card is a sentence; an open card turns the sentence into fields.** Each protection is a card that, closed, says in one sentence what it does ("Bans for 7 days an address that tries 5 accounts that do not exist within 10 minutes. You get an email."); render the sentence twice from one template, text when closed, fields when open. The whole closed card is clickable (Edit is only a visual target; hover `inset 0 0 0 1px line`). Opened, it spans the full width with an ink outline (`grid-column: 1 / -1; box-shadow: inset 0 0 0 1.5px ink; padding-block: 16px`) and the same sentence (15px, line-height 2.3) holds inline fields that look like underlined words (`.ui-sec-in`, `width: (n + 2)ch`, 14.5px weight 700, `border-bottom: 2px solid ink; border-radius: 6px 6px 2px 2px`, disabled muted `.6`), plus everything else at once (Watch first or Ban, ban length, Email me, trap names, countries). A watch-mode rule explains what Ban would do. Seconds fields show a human hint ("3600 seconds 1h"); a prefix field (IPv4 8 to 32, IPv6 8 to 128) explains its effect. Number fields (with `min`/`max`) commit `onchange` or on Enter, not each keystroke. A switched-off card keeps a readable head while its sentence turns muted (`.ui-sec-card.is-off .ui-sec-sent`). Status tags say what an enabled rule does: Bans (red), Watching (amber), Alerts, Always on, Stops mailboxes (Outgoing spam, or "Needs a Read-Write key" without that key), Beta, Needs MaxMind GeoIP; Fail2ban shows "No answer" when mailcow did not answer. Screen reader: inline fields carry descriptive `aria-label`s ("Failed logins before a ban"). v3: security.js:1109-1194, 1270-1317; ui.css:820-873.
- **FS-12 An opened card comes to the top and takes the focus.** One card is open at a time. Opening it scrolls its top to the top of whatever scrolls it (the tab on a wide screen, the page on a phone, below the sticky tabs) after the closing card has changed the layout (after `requestAnimationFrame`, offset 10px, `scroll-margin-top: 10px`), even when its top was already in view; with too little content under it the scroller stops at its end with the card in full view. The card (`tabindex="-1"` with `aria-label`) then takes the keyboard focus with `focus({ preventScroll: true })`. At 1000px and below the side panel moves above the list (5 countries, no networks) and cards become one column. Keyboard: `:focus { outline: none }` vs `:focus-visible` 2px ring offset 2px, so a mouse click leaves no outline and tabbing shows the ring. Pitfall: #350 added room under the grid so the last card could reach the top; #352 removed that empty space, so an opened card goes to the top when there is content under it and otherwise the tab scrolls to its end with the card in full view; #366 added `onlyIfAbove` to leave an element whose top is already in view, which only the Security list uses now (`securityListToTop`), not the cards. On a phone the tabs stick to the top of the page and would cover the card's head, so subtract the sticky tabs height only when they are sticky inside the scroller. v3: `securityOpenCard`, `securityScrollTo`; security.js:966-997, 1308, 534-537; ui.css:828-834, 886-892.
- **FS-13 Card on/off switch placed first; a disabled switch says why.** Each card's switch opens its head, before the name, with no On/Off text (track 36x20, knob 16px, `.15s`, green when on); Fail2ban, which has no switch, keeps its name aligned. Toggling never opens the card. A disabled switch (`.55`, `not-allowed`) explains why in its `title` tooltip ("Needs MaxMind GeoIP", "Settings are not migrated yet", "Editing settings is off"); a card that is off greys its sentence. Screen reader: `role="switch"`, `aria-label` = protection name. Pitfall: #352 took three commits: first an On/Off switch beside Edit, then the switch on the line of the name with no On/Off text, no Off tag or check mark and no count of what it caught, and finally the switch first in the head. v3: security.js:1299-1304; ui.css:841, 856-866.
- **FS-14 A few short choices are a segmented control.** Two to four short choices are a segmented control instead of a dropdown: the chosen one lifts out as a white pill (`.ui-seg button[aria-pressed="true"]` bg `--ui-bg`, `box-shadow: 0 1px 2px rgb(0 0 0 / .08)`). Picking presses it and counts as a change; a hidden input holds the value so the form saves it like any field; an unknown stored value shows the first segment pressed. In settings it sits at the end edge with Reset under the description. A segment that cannot be picked is a disabled button, so clicks do nothing, and its `title` gives the reason ("Banning needs the Read-Write API key"). Screen reader: `role="group"` with `aria-label` or `aria-labelledby`; each segment `aria-pressed`. Pitfall: in #401 the Verify SSL option labels were first shortened so they fit the field, then shown as Off, Automatic and On buttons, then aligned with the toggles and marked changed like other settings. - **FS-15 Chips with an Add field and suggestions from real data.** Multi-value fields are chips (`.ui-sec-chip`, mono 12px, radius 6px), each with a small muted × button (`title="Remove"`). An Add field takes a typed value; Enter adds. - **FS-22 Prove the credentials before enabling sign-in.** Require proof of the credentials before enabling anything that can lock the user out. Turning Basic Auth on without a password stops the save ("Cannot enable Basic Auth without a password. Please set a password first.").
