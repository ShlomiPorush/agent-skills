# UI behavior rules (v3 style): Tables and lists

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `0210d15` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Tables and lists

- **TB-1 Click a column header to sort.** Clicking any column header sorts the table by that column with no per-page wiring: one delegated `click` listener on `document` for `.ui-tr-head > *` (div tables) and `thead th`. A column is numeric if any row parses as a number (TB-2); a numeric column sorts high to low first (biggest, most recent first), a text column A to Z first; each further click on the sorted column reverses it, with no third "unsorted" state. Headers with no text and an "Action"/"Actions" column never sort; opt out with `data-nosort` on the table or a header; tables in help and release notes (`.markdown-body`) do not sort. A list sorted on the server (`data-sort-handler`) sorts only on headers with `data-sort-key` and hands the field and direction to the page (TB-4); every other table remembers its order in memory and puts it back after a refresh (TB-3). The keyboard and phones sort too: each sortable header label is a `<button class="ui-sort-btn">` (Enter and Space sort; a header that already holds a button, link or input keeps it instead), and the arrow follows `data-sort-state`. Sortable headers get `cursor: pointer; user-select: none`; the arrow is a CSS triangle `::after` (`border-inline: 4px solid transparent`, 5px top or bottom, `margin-inline-start: 5px`) at `opacity: 0` while the state is `none`, previewed as a faint down arrow at `.35` on hover with a pointer (`@media (hover: hover)`) or while the header holds the focus; the sorted column turns ink with a solid arrow (down for descending, up for ascending). A stacked list (`.ui-stack`, `.ui-dm-cards`) whose header row phones hide gets a Sort picker above it (the shared picker labelled Sort, with "Default order" until a column is sorted and the sorted column marked ↓ or ↑; picking the sorted column turns it around), unless the page has its own control (`data-phone-sort="off"`). A list sorted on the server puts the focus back on the same header button or picker once it is drawn again, for up to 5 seconds, unless the user moved the focus elsewhere or the answer is no list. Keyboard: the header button shows a focus-visible ring (2px `--ui-focus`). Screen reader: `aria-sort` (`none`, `ascending`, `descending`) stays only on a real `th`, kept current; a div list's header button says its order in visually hidden words (", sorted ascending"). Pitfall: server-paged tables sort on the server so the order covers every page, and a cell with extra markup (the not-on-server note) needs `data-sort` (#415). Helpers: `uiSortEnhance`, `uiSortBy`, `uiPhoneSortSync`, `uiSortFocusBack` in utils.js. - **TB-2 Sort reads cells by meaning.** The sorter reads cells the way a person does. `data-sort` on a cell overrides its text (number if it parses, else lowercase text). Sizes `<number> b|kb|mb|gb|tb`, comma or dot decimal, x1024^n ("900 KB" below "1.2 MB"); durations s, sec, min, m, h, d, w, mo (30 d), y (365 d), optional `up `, `ago` values negated, "just now" = 0 (so "just now", "6 min ago", "3 h ago" sort by real time, most recent first when descending, and "2 d" above "13 h"); numbers strip commas, k = 1e3, m = 1e6, `%` accepted ("1,920", "45%", "3.4k"); dates `d{1,4}[./-]d{1,2}[./-]d{1,4}`, dotted = DD.MM.YYYY, others MM/DD/YYYY, the 4-digit part is the year, optional `HH:MM(:SS)`, read as UTC (only the order counts, and the browser's zone would fold the hour it skips). Remove `.ui-sec-unit` and `.ui-phone-only` from a clone before reading, so phone-only unit text is ignored; "-" counts as empty, and rows with no value stay last in both directions. Text compares with `localeCompare(..., { sensitivity: 'base' })` (case and accents ignored); equal values keep their order by original index. A sort unit is a `.ui-tr` plus its following non-row siblings, so an opened detail panel travels with its row; each `.ui-tr-group` starts a segment, so group header rows stay put and their rows sort within the group; `<tr data-sort-fixed>` or single-cell rows (such as "No matches") are appended after. v3: `uiSortUnits`; utils.js:1070-1142.
- **TB-3 The chosen order survives refreshes; sort menu and header stay in step.** When a page reloads its data (polling, filter change, redraw), the table comes back in the order the user picked. Remember the order per table in memory (not across page loads) under `<id of table or nearest ancestor with id>|<header labels joined>`; a body `MutationObserver` batches to one pass per animation frame and reapplies only if `data-sorted-by` differs. Where a page also has a sort dropdown the two never disagree: picking in the dropdown clears the header sort (`uiClearTableSort(ownerId)` forgets the order of every table under that owner), and a header sort updates the dropdown. Quarantine dropdown `newest` | `score_desc` | `score_asc`, re-rendered from the last loaded data (`quarantineLastData`) without refetching, no-score items last. Mailbox list: a header combination the dropdown lacks is added to it, named after the existing option ("Failed (Low to High)"), value `<key>-<asc|desc>`. v3: `uiClearTableSort('<owner id>')`, `mailboxStatsSortBy`; utils.js:1008, 1020-1023, 1144-1149, 1260-1310; app.js:2808-2848; mailbox-stats.js:723.
- **TB-4 Server-paged header sort.** On a list paged by the server, a header click sorts across every page, not just the visible one, starting again from page 1; a second click turns it around; the search, paging (or loading more as the list scrolls) and a single delete keep the order, and pages continue one another without repeating or skipping. Mark it `<table data-sort-handler="myFn">` with `<th data-sort-key="field">` (or a `.ui-table` div list with `data-sort-key` on its header cells); only headers with `data-sort-key` sort, and the click calls `window.myFn(key, 'asc'|'desc')` with the TB-1 direction rules; the page redraws and writes `aria-sort` into its header, which utils.js keeps on a real `th` and turns into `data-sort-state` plus hidden words on a div list (Manage Reports, suppressions, Devices and the mailbox list are all div lists). Defaults: reports `created_at desc` (not sent in the URL), suppressions `created_at desc`, devices `last_seen desc`, mailboxes `sent_total desc`; on Devices both "Reset filters" and "Clear filters" also reset the sort. Use stable tiebreakers (import date, type, id), empty values last. Screen reader: each sortable header says its order (`aria-sort` on a `th`, ", sorted descending" in the header button of a div list). Pitfall: sorting one page of a paged list was rejected in #319; #416 reused the server-paged header recipe from the Devices page (#370) for Manage Reports. v3: `data-sort-handler`, `data-sort-key`; utils.js:1029, 1177-1181, 1272; dmarc.js:1105-1117, 1257, 1317; spam_filter.js:456-463, 560; devices.js:8-18, 113; mailbox-stats.js:463, 717-735.
- **TB-5 Rows stay while a list reloads; dim only after 200ms.** A search, sort, page change or delete keeps the current rows on screen until the answer replaces them in place, so a dialog or card never collapses to a spinner and jumps back. Start a 200ms timer that dims the rows to `opacity: .6` (no layout change) and clear it when the answer lands. Show the loading state only on first open; the search box keeps its focus and text; counts in filter buttons keep their last values while another list loads instead of blanking. Screen reader: `aria-busy="true"` while loading. Pitfall: every reload replaced the All reports list with a loading spinner before the request, so the dialog collapsed to the spinner's height and jumped back when the rows returned; #416 kept the rows, verified by a recording of typing, sorting and paging with no loading state and a constant dialog height. Combine with SV-7 so a slower older answer cannot replace a newer one (#370). v3: `loadReportsManagementPage`; dmarc.js:1126-1128, 1238-1253; security.js:25, 617-622.
- **TB-6 Lists load more as their end scrolls into view.** Long lists have no page buttons: a sentinel after the list (`#messages-more`, `#security-more`, `#mailbox-stats-more`, `#suppression-more`) watched by an `IntersectionObserver` with `rootMargin: '0px 0px 600px 0px'` (Messages) or `400px` (Security, Mailbox Stats, the Outbound Suppressions list) loads the next page of 50 before the user reaches the end. The Messages observer root is the list's own column when it scrolls (`scrollHeight > clientHeight + 1` or overflow-y not visible), else the page. A line under the list says "Loading more..." while more exist; at the end Messages always says "All N messages shown", while Security ("All N shown"), Mailbox Stats ("All N mailboxes shown") and Suppressions ("All N suppressions shown") say it only when there was more than one page. A failed page turns the line into "Could not load more messages. Try again" (Suppressions: "Could not load more suppressions. Try again") with a link-style button; Security says "Could not load more: <error>". Dedupe by `data-key` (correlation key), by IP, by username or by suppression id so new data never makes a row appear twice. A Security refresh reloads `min(200, max(50, shown))` rows and a Suppressions refresh reads again every page already shown, so the list does not shrink back; an open row stays open while more load. Screen reader: end line `aria-live="polite"`. Pitfall: paging and Show all buttons were replaced (Messages #285, Statistics #377, the suppression list #459), and Security went from ten rows and Show all (#279) to 25 at a time (#352) to server-built pages of 50 with a cursor (#366), so an address that changes list meanwhile does not shift the rest. A short page may leave the end still in view, so check again after drawing and load again if `sentinel.top < max(container.bottom, innerHeight) + 600`. v3: `renderMessagesList`, `watchMessagesEnd`, `loadMoreMessages`; app.js:1250-1321; security.js:37, 150-202, 647-649, 703-715; mailbox-stats.js:256, 317, 542-547; spam_filter.js:465-623.
- **TB-7 A new list, search or filter starts at the first row.** Changing the list, period, country, network, search or any filter reloads from the first page (`page = 1`) and scrolls the list back to its first row (`container.scrollTop = 0`), so a new list never opens in the middle. Reset before the request and again in the next frame after the rows are drawn (`requestAnimationFrame`), scrolling only if the list top is above view. Pitfall: the browser's scroll anchoring carried the new rows down to where the old list ended, because the content is short while they load; #366 resets again after the new content renders, not only before. v3: `securityListToTop`; app.js:2372-2391, 4011-4014; security.js:188-191, 520-547.
- **TB-8 Whole row opens; inner controls keep their own click.** A click anywhere on a row opens its details, while buttons, links, checkboxes, menus and copyable values inside keep their own action: `quarantineRowClick` returns early for targets in `button, a, input, select, label, .copyable, [role="menu"]` (Security: `securityRowClick` with `closest('button, a, input, .copyable, .ui-sec-detail')`, the detail calls `stopPropagation`; Needs attention alerts: `uiAlertRowClick` with `button, a`). A click that ends selecting text in the row opens nothing, so values can be copied: every row opener asks `uiRowHeld(event)` first (an inline `if (!uiRowHeld(event))`, or inside `quarantineRowClick`, `securityRowClick` and `uiAlertRowClick`), which holds the row when selected text lies in the row and the click ends a selecting gesture: the press moved more than 3px (a capture `mousedown` listener records where it started), `detail > 1` (a double or triple click on a word) or Shift (extending a selection). A plain click, also on text that is still selected, opens the row, and so do Enter and Space (`detail` 0); nothing stops the event, so the rest of the page still gets the click (an open picker closes). A new row that opens on click asks it too; a scan in `keyboard.a11y.cjs` fails otherwise (a Settings choice card and a sheet backdrop are not rows). Rows that open something show a pointer and, only with a pointer that hovers (`@media (hover: hover)`), a hover tint `color-mix(accent 5%)` (domain, mailbox and dtable rows accent 4%; DMARC rows, Security rows and Needs attention alerts ink 3%); rows with nothing to open have no pointer or hover (`.is-static` `cursor: default`); `.ui-sec-row.is-open` takes the page background (`--ui-bg`). Where a real focus target is needed, the first cell holds a link-styled button whose click bubbles to the row. Keyboard: a row marked `data-row-open` with `tabindex="0"` (`role="button"` on div rows: Messages rows, the dashboard's recent messages, journey legs and the journey toggle, Rspamd map rows; also Rate Limits sender rows) opens on Enter and Space when the row itself has the focus, through one `keydown` listener in utils.js (a button or copyable value inside keeps its own keys), and shows an inset 2px focus ring; DMARC rows carry `button.ui-dm-link` in the first cell; Security rows are `role="button"` with their own Enter and Space handler (AX-5). Pitfall: Quarantine first had only the subject as the link (#271); #310 made a click on the row open the message like the Messages list, and #340 made sender, recipient and ID plain text in the row (the dialog still copies them) so a click on them opens the row. Before all rows did this (#473), only Quarantine and Needs attention checked `window.getSelection()`, and that check also swallowed a plain click on text still selected. v3: `uiRowHeld`, `uiAlertRowClick`, `quarantineRowClick`, `.ui-tr[data-href]` or `[onclick]` for the hover tint; app.js:1947, 1972-1976, 2331-2366, 2954-2959; security.js:452, 465-469; dmarc.js:271, 498, 510, 715, 826; ui.css:204-205, 299-301, 704-709, 1243-1244, 1506, 2565-2566, 2584; utils.js:1194-1203, 1205-1218.
- **TB-9 Row expands in place; details load when revealed.** Clicking a row opens its details right under it across the full row (`grid-column: 1 / -1; cursor: default`); clicking again closes it; clicks inside the details do not collapse it. A chevron turns 90 degrees (180 for event toggles) with `transition: transform .15s` and points the reading direction in RTL. Data only the details need (raw log lines, a rule's history) is fetched when they open, with "Loading...", an error line or an empty line: Security keeps one row open at a time and fetches raw lines (limit 40) once and keeps them ("Could not load the log lines.", "No log lines for this address."); on a phone the open address shows in a sheet from the bottom instead, so the list stays where it was; a Fail2ban network row (`.is-net`, `.is-static`) has no log lines of its own and does not open; rule history (limit 20) reloads each time it opens ("No actions recorded yet", "Failed: <reason>"). - **TB-11 Problems first.** Lists sort by a problem rank first, then the natural key. Containers: rank stopped 0, running 1, ignored 2, then name. DMARC senders: failing before passing, then by volume (`(passPct >= 50) - ... || b.total - a.total`), grouped by network owner (`asn_org || source_ip`) so one provider is one row; SPF and DKIM shares weakest first; blocked senders by most recent hit; domains before mailboxes in configured limits.
