# UI behavior rules (v3 style): Accessibility and motion

Part of the `v3-ui-style` skill. Companion to `references/v3-design-principles.agents.md` (look, behavior principles, interaction rules, what not to copy). The skill's SKILL.md maps ID prefixes to area files. Paths are relative to the skill folder.

How to read:

- One bullet is one behavior with a stable ID (`DS-1`). A rule may name rules of other areas by ID; when your screen uses that part, read those rules too.
- **Pitfall** marks a behavior whose history shows a failed earlier attempt, a revert or a fixed bug. It says what went wrong and what fixed it. Do not skip it: it is the reason the behavior is shaped the way it is.
- `v3:` gives the v3 helper and `file:line` in the bundled code under `references/v3-code/`, a copy of the mailcow Logs Viewer frontend at commit `72e43c4` (`ui.css` is under `assets/css/`). Start at the cited lines and widen to the whole function and what it calls when the bullet is not enough. The rules were first written against the earlier snapshot `deb075d`, then checked rule by rule against this code.
- Rules the interaction fixes changed (October 2026) start with what v3 does now and name its helpers; the part marked "Before the interaction fixes" describes the code before them. Where the two differ, the first part is the rule; details the first part does not cover still hold. A sentence that starts "Before the auto-refresh layer" or "Before #509" describes older code in the same way: history, not the rule.
- The principles file's section "Interaction rules v3 follows since its interaction fixes" lists what those fixes added. Never copy anything listed there under "Do not copy".

## Accessibility and motion

- **AX-1 Visible focus for keyboard users only.** Keyboard users see a clear blue ring on whatever has focus; mouse clicks do not leave one: `:where(.ui) :focus-visible { outline: 2px solid var(--ui-focus); outline-offset: 2px }`, focus color light `#1F5FBF`, dark `#7DB3FF`; `:where()` keeps specificity at zero so components can override. Inside scrolling lists (search, pickers, folds) and on rows that open on click (`[data-row-open]`) draw the ring inset (`outline-offset: -2px`) so it is not clipped; a row's chevron button (`.ui-row-chev`) keeps the 2px offset with a 3px radius. Text fields show a dark accent border on focus instead of a glow, also for mouse focus (`outline: none; border-color: var(--ui-accent)`, legacy `box-shadow: none`). Repeat the rule on every new interactive element (switches, cards, flyout items, picker options, folds, rows, row chevrons). v3: ui.css:145, 178, 1157, 1772-1773, 2813, 2872, 3145.
- **AX-2 States are ARIA attributes that also drive the styling.** The visual state and the announced state are the same attribute; style from ARIA attributes, never from parallel classes: chips, facets, segmented controls, log toggles, chart bars and presets use `aria-pressed`; disclosures (Filters button, pickers, logs side, quick filters, event toggle, protection summary, custom range, alias chevrons, row chevrons, the delivery journey toggle, sidebar toggle) use `aria-expanded`; navigation, settings categories and log services use `aria-current`; sortable headers `aria-sort` on a real `th` (a div list header has `data-sort-state` and its order in hidden words, TB-1); page, dialog and search tabs `role="tab"` with `aria-selected`; picker options `role="option"` with `aria-selected`; Manage Reports `aria-busy`. Some controls still take their look from a class that is set together with the attribute: page and dialog tabs `.active`, search tabs `.is-on`, the DMARC policy cards `.is-on` beside `aria-checked`, the phone menu `.mobile-menu-item.active`; keep the class and the attribute in step there. A pressed chip or facet inverts (`[aria-pressed="true"]` on `.ui-chip`, `.ui-fct`: accent background, light text; colored chips fill with their color); a pressed chip's count is at `opacity: .8`, a pressed facet's count takes the text color. The settings mobile picker has the sr-only label "Settings category". v3: ui.css:194-198, 403, 547-552, 574, 599, 945, 995, 1048, 1212, 1283, 1343, 1501, 1612, 2340, 2349-2351, 2377-2382, 2606-2614, 2801; settings.js:1728, 1751-1753, 1921-1925; utils.js:2706; dmarc.js:820-825; app.js:4275.
- **AX-3 Live regions for counts and loading.** Use polite live regions for counts that change under the user: the save bar's unsaved-change count `aria-live="polite"`, the "Loading more..." line at the end of a list polite, the DMARC policy explanation, and "No matches" in a picker `role="status"`. The auth banner is a status; toasts are `role="status"`, error toasts `role="alert"` so they interrupt. v3: index.html:576, 851; utils.js:200, 759, 2714; security.js:687.
- **AX-4 Icon-only controls are named; decoration is hidden.** Never ship an icon button without a name: `title` plus `aria-label` on theme, logout, GitHub, container logs, close, More and search, so hovering shows a tooltip and screen readers read it; `title` is the only label for rail nav items and for the help button beside each page title (`title="Help - <page>"`; the Outgoing spam help on Security also has `aria-label`). An icon action keeps a visually hidden text (`.ui-head-icon-text { position: absolute; width: 1px; height: 1px; overflow: hidden; clip-path: inset(50%); white-space: nowrap }`). Decorative parts (grip, reading gauge, lock, toast icon, search icons, key hints, chevrons, crumb separators, chart SVGs, flags) get `aria-hidden="true"` or `alt=""`; icon results and charts get spoken names with `role="img" aria-label` (DNS icons, chart columns, sparklines); the lookup icon is `aria-label="Look up on <list>"`; bare inputs in sentences and lists and checkboxes carry descriptive labels. v3: index.html:400, 409, 441, 454-516, 587, 1161, 1482; ui.css:3215-3219; utils.js:182, 764, 878, 1829, 1871; index.html:915-916; search.js:261, 331; security.js:1320.
- **AX-5 The keyboard reaches what a click reaches.** A row that opens on click has `tabindex="0"` (and `role="button"` when it is not a table row) and opens on Enter and Space when the row itself has the focus (`data-row-open`: message rows, Rspamd map rows, rate limit senders, the delivery journey and its legs); a row that holds controls of its own opens from its chevron, a `<button>` with `aria-expanded` and `aria-controls` (domains, mailboxes); a row with a primary button inside (a DMARC domain, a quarantined subject) needs nothing more. Security address rows are `role="button" tabindex="0"` with `aria-expanded` and toggle on Enter or Space only when the row itself has the focus; a network ban row opens nothing and has neither. Use real buttons; where a label must act as a button, add role, tabindex and a key handler: the Upload Report label is `<label tabindex="0" role="button" onkeydown=...>` where Enter or Space call `preventDefault()` then `click()` on the hidden file input, named by `aria-label` and a visually hidden span. Dashboard chart bars are buttons (`aria-pressed`). In the sidebar flyout ArrowRight on a navigation item opens it and focuses its first entry, ArrowDown and ArrowUp move between the entries and wrap around, and Escape or ArrowLeft (ArrowRight when the page reads right to left) close it and return the focus to the item. An opened Security settings card takes the focus. In a dialog Enter on a button presses that button: a dialog whose own key handler confirms on Enter (Verify credentials, Disable features) skips it when the focus is on a button, so Enter on the X or Cancel never confirms (#509). The search field names its active result with `aria-activedescendant`; dialog tabs have `role="tab"` and `aria-selected`; loading blocks are `role="status"`; a status shown only as a coloured dot has `role="img"` and a label. Helpers: the `data-row-open` key handler in utils.js, `.ui-row-chev`. Before the interaction fixes (history; where it differs from the text above, the text above is the rule): Use real buttons; where a label must act as a button, add role, tabindex and a key handler: the Upload Report label is `<label tabindex="0" role="button" onkeydown=...>` where Enter or Space call `preventDefault()` then `click()` on the hidden file input, named by `aria-label` and a visually hidden span. Dashboard chart bars are buttons; the sidebar flyout works with arrow keys and Escape; an opened Security card takes the focus; Security address rows are `role="button" tabindex="0"` with `aria-expanded`, and Enter toggles only when the row itself has focus. v3: settings.js:112-119, 162-166; index.html:1158-1164; security.js:431-444, 1011-1016; utils.js:1472-1481; app.js:3009-3010, 6471-6479, 6522-6526.
- **AX-6 Focus kept or moved on purpose.** On open, focus the first thing the user will type into; on close, return focus to the opener: the custom log range focuses From; the regex wizard focuses its input; Add Suppression focuses the address; the policy picker moves focus with the pick; the period picker returns focus to its button on close; Filters panels focus their first field; the destination dialog opens in Name; rate-limit search keeps focus because rows are hidden in place. v3: logs-viewer.js:267; spam_filter.js:873, 1270; dmarc.js:825; mailbox-stats.js:661; rate-limits.js:457.
- **AX-7 A choice of three as a real radio group, with a live explanation.** The DMARC record window offers None, Quarantine and Reject as three cards that say what each does, each with its level tag (Monitoring, Partial, Enforced) and a 4px bar in that color at its start; the current one carries a "Now" tag and the next stricter one is preselected (none -> quarantine, quarantine -> reject, reject stays). The selected card gets a 2px focus-color border and 6% tint with padding 12 -> 11 so the size does not jump. The explanation below updates as the choice moves: the current policy says "This is the policy in place." ("The strictest policy is in place." for Reject); None says "With p=none, mail that fails is delivered and only reported."; every choice other than the current one also shows the record to publish: the published record with only `p=` changed so its other tags stay, or `v=DMARC1; p=<pick>; rua=mailto:dmarc@<domain>` when there is none; for Quarantine and Reject it says first whether the domain is ready ("No data." when the last 30 days hold no mail; "Ready." when every sender that passes on most of its mail (50%+) passes on 95% or more; otherwise "Not yet. A sender passes on under 95%: fix it first.", or "Not yet. No sender passes on most of its mail: set up SPF or DKIM first." when no sender does), how many messages of the last 30 days would have been refused or sent to spam (every message that failed DMARC, whoever sent it). On phones the cards are one column. Keyboard: `role="radiogroup" aria-label="Policy"`, each card `role="radio" aria-checked`, roving `tabindex` (0 on the picked, -1 on the rest), focus follows the pick, ArrowUp/Left and ArrowDown/Right move the choice and wrap around with `preventDefault`; the plan is `aria-live="polite"`; card `:focus-visible` ring. v3: dmarc.js:782-843; ui.css:2908, 2984-2993, 2998, 3032.
- **AX-8 Reduced motion and the motion inventory.** Motion is short and quiet: `.08s linear` reading gauge; `.12s` flyout; `.15s` switches, chevrons, grip, search box, copy hover; `.18s ease` sidebar fold; `.2s ease` sheet and dialog corner radius, sheet transform, More veil; `.2s ease-out` More sheet slide; `.22s ease` search widening; `.3s` meter width and toast fade; `2s ease` search flash; `1s linear infinite` spinners; drags turn transitions off. Animations are part of the design and stay when the system asks for reduced motion: the owner turns animations off in the operating system and still wants them in the app. Add no reduced-motion override; v3 removed the one it had on the phone More sheet. v3: ui.css:912, 918, 1287-1303, 1706, 2540, 2687, 2775, 2783, 2829, 3141; utils.js:1914, 1934, 2596, 2619.
- **AX-9 Cursor language.** Map each interaction kind to one cursor: pointer on clickables; default on the current or static item (current journey leg, static rows, open cards, details areas); not-allowed on disabled and locked controls (`:disabled`, `[aria-disabled="true"]`; buttons `opacity: .5`, fields `.6`, `cursor: not-allowed`); wait on the save bar while saving; grab and grabbing on the sheet grip; zoom-in on a sparkline; help on DMARC superscript notes. Screen reader: `aria-disabled` is supported for buttons. v3: ui.css:168, 179, 519, 771, 781, 841, 918-920, 1775, 1929, 2194, 2903.
- **AX-10 No accidental text selection on toggles.** Double-clicking a summary, a toggle or a sortable header does not select its text: `user-select: none` on repeated-click targets only (`.ui-collapse > summary`, `.ui-md-toggle`, sortable headers). v3: ui.css:512, 719, 2607.
- **AX-11 Accessibility checks run in CI.** Accessibility is tested, not assumed: the CI step "Accessibility of the pickers and the layers" runs every `.github/tests/*.a11y.cjs` in a real DOM (jsdom, with axe-core in the picker and keyboard suites): the shared pickers after the WAI-ARIA listbox and dialog patterns (names, focus, arrows, Escape, one open at a time), sortable headers as buttons and rows that open on Enter and Space, the layers (Escape and Back close only the top layer, focus moves in and back, what lies under the top layer is inert) the unsaved-changes questions (Stay, Leave, Back undone while asking) and every dialog's frame and close rules (`popups.a11y.cjs`, DS-24); the UI inventory reads picker options and pickers so they stay guarded like inline handlers, and reads the close functions passed to `uiDialog`. v3: .github/workflows/ci.yml:119-125; .github/tests/pickers.a11y.cjs:1-6; .github/tests/keyboard.a11y.cjs:1-6; .github/tests/layers.a11y.cjs:1-6; .github/tests/unsaved.a11y.cjs:1-6; .github/scripts/ui-inventory.cjs:198-204.
- **AX-12 Native disclosures for folds.** Prefer `<details>` over custom toggles: collapsible panels are `details.ui-collapse[open]`, the head toggles its body, the default triangle is gone (`list-style: none`, webkit marker hidden), a chevron turns over (`transition: transform .15s ease`, open `rotate(180deg)`; DMARC fold `rotate(45deg)` -> `rotate(-135deg)` with an inset focus ring -2px), summary hover `accent 4%`, and the head gets a divider when open. "Show all" summaries are only as wide as their text (`.ui-bl-all summary`, `.ui-dns-more summary` `width: fit-content`). Select-like buttons and toggles rotate their arrow when open with `transform .15s` (`.ui-select-arrow`, `.ui-md-toggle svg`, `#date-range-arrow`, `.ui-nav-toggle svg`). Keyboard: native details/summary gives keyboard and screen reader support for free. v3: ui.css:341, 512-514, 717-725, 1690-1691, 1794-1795, 1920, 2680, 2866-2872.
